Create a test dataset

Turn knowledge you approve into questions and expected answers that can test an Agent.

What this step does

lladar create test-dataset reads knowledge files or directories and writes records with a question, expected answer, and an empty place for the Agent's later response.

Discover a GitHub dataset

lladar create test-dataset --from-github https://github.com/hsinmosyi/TWBias --count 20 --output dataset.jsonl

Choose --knowledge or --from-github. The Agent finds actual public text datasets and records answer origins. Every output question is covered by dataset.generation-report.md, with source excerpts, fixed-version links, transformations, model checks and limits. Saved originals are in dataset.sources.json. Review generated criteria before running the target Agent.

Basic command

lladar create test-dataset --knowledge KNOWLEDGE_PATH --output dataset.jsonl

Repeat --knowledge to combine inputs. An output ending in .jsonl names the exact file; an output directory receives a new timestamped dataset.

Choose a generation method

The Agent follows the selected Skill: it can generate questions directly from source passages or use an evidence graph for concept probes. Graphs are optional. Final candidates are validated before publishing; a .graph.json sidecar is written only when a valid graph is used.

Use a custom local Skill

Pass one --skill DIRECTORY to use your own generation method. The directory must contain SKILL.md. For example, a support team can require questions about returns, delivery, and refunds.

lladar create test-dataset --knowledge policy/ --skill skills/support-qa --output dataset.jsonl

Watch token usage

From v0.17.0, create test-dataset accumulates the input and output tokens reported by the model provider. Verbose output is enabled by default: a [TOKENS] line updates the cumulative counts after each model response, including tool rounds and retries. It does not update token by token while a response is pending.

lladar create test-dataset --knowledge policy/ --output dataset.jsonl --verbose --log logs/create.log

For example, an update may look like this; the numbers below are illustrative:

[TOKENS] stage=generation cumulative input=4000 output=600 total=4600; unreported calls=0

LLaDAR reads usage returned with the existing model response through Akasha/LangChain. Collecting these counts does not send the prompt again or make an extra token-count API call. Inventory, reconciliation, generation, audit, coverage review and repair calls contribute to the total when those stages run.

--no-verbose hides these updates while still saving usage. --resume retains the work-session totals; the operation report also shows the usage added by the current invocation. Missing provider usage is unknown, not zero, and older runs cannot be reconstructed from their text. See token fields and accounting limits.

Inspect the result

Read the dataset before testing an Agent. Its .generation.json sidecar records the sources, selected Skill, settings, any skipped input, and a token_usage summary with totals and per-stage counts. Usage is also saved in the work-session checkpoint and dataset.jsonl.operation.md. You can include the saved usage in a coverage report.

Need to test a conversation?

If your goal is to observe behavior over multiple turns, use create situation. A knowledge file is optional there.
