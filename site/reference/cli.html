Shared options

lladar --version prints the installed package version. Add --log PATH to any workflow command, or before the command, to save emitted terminal output to a new UTF-8 file while keeping it visible. Logs contain progress, traces, summaries and handled errors without ANSI color codes. --no-verbose suppresses detailed output in both destinations. Parent directories are created automatically; existing log files are preserved even with --force.

lladar create test-dataset --knowledge policy/ --output dataset.jsonl --log logs/create.log

Dataset generation methods

The selected Skill guides direct QA or optional graph generation. Python may produce or repair candidates; every delivery path faces final validation. The JSONL format is unchanged, and .graph.json is optional.

create situation

Compile an observation, stopping rule, declared variation axes, and fixed judging method into a situation JSON. Knowledge is optional; this is separate from the three-field QA dataset.

lladar create situation (--instructions TEXT | --instructions-file PATH) (--stop-criteria TEXT | --stop-criteria-file PATH) --max-turns N --output PATH [OPTIONS]
ArgumentDefaultUse
--instructions TEXT / --instructions-file PATHOne requiredOverall generation, execution and default evaluation instructions; text/file inputs are mutually exclusive. Legacy --observe / --observe-file aliases remain.
--stop-criteria TEXT / --stop-criteria-file PATHOne requiredSemantic stopping rule, given directly or read as UTF-8 from a file; mutually exclusive.
--max-turns NRequiredPositive maximum number of user/target turns in one scenario.
--knowledge PATHNone; repeatableExisting .md or .txt file. LLaDAR saves path and hash and checks it again at run/eval.
--output PATHRequiredDestination situation JSON. Existing output is rejected unless --force.

The result stores the observation, stop text, knowledge hashes, generation and run methods, variation axes, and evaluation rubric. See the full multi-turn workflow.

run-agent

Run an Agent through an inspected project or a calibrated question webpage, verify the route, and fill actual_response in a new responses file.

Choosing the target

--project PATH can be enough on its own: LLaDAR learns the public interface and startup procedure from source and documentation. With the necessary runtime configuration available, it can start a required service in an isolated project copy and stop only what it started. Missing startup, authentication, or API contract details require clarification.

Add --service-url URL only to use an already running test service. It supplies the base address, not a startup command or the HTTP method, route, payload, or response format; those still come from project inspection. LLaDAR does not start or stop that existing service. The option is --service-url, not --service-api.

Use --page-url URL instead when you have a normal question webpage without project source: browser sign-in and calibration record the request for replay, then the model extracts response text. It cannot be combined with --project or --service-url. With neither target option, LLaDAR inspects the current directory. See the three-path selection guide.

lladar run-agent artifacts/dataset.jsonl --project path/to/agent --no-interactive --output artifacts/responses.jsonl
lladar run-agent artifacts/dataset.jsonl --project path/to/agent --service-url http://127.0.0.1:8000 --output artifacts/responses.jsonl
lladar run-agent artifacts/dataset.jsonl --page-url https://example.test/chat --output artifacts/responses.jsonl

Direct model extraction is the only browser answer path, default gemini:gemini-3.8-flash. One YES approves both disclosed website requests and real response content transfer before GEMINI_API_KEY/GOOGLE_API_KEY is loaded. The two approval flags retain separate scopes; both skip approval, not MATCH review. MATCH compares the full verification response and extracted text in the color terminal (stderr), with no HTML tab. NO_COLOR or TERM=dumb selects plain text. Redirected review output is refused; terminal scrollback may retain content. Browser capture remains required. Model input is capped at 120 KiB of UTF-8 JSON including framing, without truncation or retries. Valid extraction does not guarantee fidelity or answer correctness. See the run guide.

Situation execution contract

A project supplies lladar_session.py or LLaDAR generates a candidate in a project copy. Two turns in one session plus a fresh-session isolation probe must pass before scored requests. The selected --service-url is passed as LLADAR_SERVICE_URL; the adapter must use the actual public API. --page-url is unsupported with situation mode. The run JSON records the adapter hash, source and any errors. See adapter calibration.

lladar run-agent --situation-config artifacts/situation.json --project example_project/situation_demo --num-scenarios 2 --output artifacts/transcripts.jsonl

eval

Use an evaluation method to judge completed responses and calculate a summary from the saved judgments.

lladar eval RESPONSES [OPTIONS]
ArgumentDefaultUse
RESPONSESRequiredQA responses JSONL or situation transcripts JSONL created by run-agent.
--output PATHevaluation.jsonEvaluation JSON to create.
--criteria TEXTNoneEvaluation requirements for the built-in method; mutually exclusive with --skill.
--skill DIRECTORYNoneA complete local evaluation method, including its standards. Replaces default typed/probe scoring too.
--situation-config PATHNoneVerify original run/config hashes. Use the frozen rubric by default; --criteria or --skill can replace evaluation without changing that config.
--model MODELgemini:gemini-2.5-flashModel used by the evaluator.
--env-file PATH.envEnvironment file supplied to the evaluator provider.
--strictOffStop the command when a per-record evaluator error occurs. Without it, the record is saved as a judge error and evaluation continues.
--forceOffReplace an existing evaluation file.
lladar eval artifacts/responses.jsonl --strict --output artifacts/evaluation.json

With neither option, existing default scoring remains. Evaluation results and reports record the effective settings, criteria text/hash or Skill source/evidence. Correctness tables require a correctness dimension.

lladar eval artifacts/responses.jsonl --criteria "Observe target wording; presence alone is not bias" --output artifacts/wording-evaluation.json

Situation judgments

Situation evaluations save validity, behavior, cited turn IDs, and deterministic counts. Failed or indeterminate trials are excluded from the observed rate.

lladar eval artifacts/transcripts.jsonl --situation-config artifacts/situation.json --output artifacts/situation-evaluation.json
