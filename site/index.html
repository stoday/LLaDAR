User guide

Generate and evaluate agent test cases

Create controlled question groups from knowledge files or import cases from an external benchmark. Run your own agent and evaluate its observed answers with source evidence.

1. Install and prepare a provider

These instructions follow the current repository source, including local changes that may not be in a published package yet. Use Python 3.11 or 3.12. From a checkout of this repository, install LLaDAR in its own environment. The examples use PowerShell.

py -3.12 -m venv .venv-lladar
.\.venv-lladar\Scripts\Activate.ps1
python -m pip install -e .
lladar --help

LLaDAR uses Akasha for model calls. Put the credentials required by your chosen provider in a local .env file or in your process environment. The default dataset model is gemini:gemini-3.7-flash; select a different Akasha model with --model if needed. Keep .env and generated runtime files out of public repositories.

Read the commands and choose output paths

Run the examples from the repository root unless a step says otherwise. In PowerShell, .\ means the current directory: .\my-agent is a project folder and .\my-agent\.venv\Scripts\python.exe is a file inside it. Replace my-agent with your real project path. A positional value follows the command name; an option such as --output PATH names a setting. The sample paths do not upload anything to GitHub Pages.

--output selects where this particular command writes its main result. Its value is a file or a new directory depending on the command. When examples start with .\, they refer to the directory where you run the command:

CommandMeaning of --outputOther files
create configTOML settings fileNone in this example
create test-dataset --knowledgeJSONL question-group fileOptional trace/cache files only when enabled
create test-dataset --convert-fromNew benchmark bundle directoryThe bundle contains cases, scoring rules, and source evidence
run-agentJSONL observed-answer file<answers>.run.json and managed run data
eval DATASET ANSWERSJSON evaluation fileFor a generated dataset, also <output stem>.items.jsonl
eval --fromNew evaluation directoryreport.json, scoring plans, and evidence inside it

.json is one JSON document; .jsonl is one JSON record per line; .toml holds editable settings; .md is Markdown text. The setup commands create .venv-lladar, activate it, install this checkout with pip install -e ., and show top-level CLI help. The target project's .venv is separate from .venv-lladar.

2. Generate a test dataset

Create a UTF-8 knowledge file, for example knowledge/plans.md:

# Membership plans
Plan A is available to customers aged 65 or older.
Plan B is available to customers younger than 65.

Run the generator from the directory containing knowledge:

lladar create test-dataset --knowledge .\knowledge --count 1 --seed 1234 --output .\test-dataset.jsonl

--knowledge accepts one or more .md or .txt files or directories, scanning directories recursively. A positive --count sets the maximum number of usable (ready) question groups; a short source may yield fewer. Skipped or duplicate candidates do not use the quota. --count 0, the default, processes every candidate. --seed makes candidate order reproducible. An existing explicit output file is protected from overwrite.

What a group contains: a source-grounded original question and reference answer, one question with key information removed, and one to four questions with controlled peer cues. Variant answers remain empty until your agent is run. The exact questions depend on the source and model.

Illustrative question group

  • Original: “Which plan applies to a 70-year-old customer?” → reference answer: Plan A.
  • Key information removed: “Which plan applies to this customer?”
  • Peer cue: “Which plan applies to my grandmother?” The cue alone does not establish the customer’s age.

The result is UTF-8 JSONL: one JSON object per line. To inspect the first record in PowerShell:

Get-Content .\test-dataset.jsonl -TotalCount 1 | ConvertFrom-Json | Format-List

If you omit --output, LLaDAR creates a collision-safe file named test-dataset-YYYYMMDD-HHMMSS.jsonl. For a quick one-file run, replace .\knowledge with .\knowledge\plans.md.

What each part of the generation command means

PartMeaning
lladar create test-datasetCreate LLaDAR test questions from the supplied knowledge documents.
--knowledge .\knowledgeRead the local knowledge folder; only .md and .txt files are searched recursively. You can also name individual files or multiple paths.
--count 1Request at most one usable ready question group. The default 0 processes all candidates; the source may yield fewer than requested.
--seed 1234Fix candidate ordering for repeatable selection. Model-generated wording can still vary.
--output .\test-dataset.jsonlWrite the generated groups to this UTF-8 JSONL file. Each line is one group, including its source-grounded original and variants.

knowledge/plans.md is your input, not a generated file. test-dataset.jsonl is the dataset passed to run-agent and later to eval. In the inspection command, Get-Content -TotalCount 1 reads the first JSONL line, ConvertFrom-Json parses it, and Format-List displays its fields.

3. Save settings for repeated runs

lladar create config --output .\config.toml

Edit config.toml, for example:

schema_version = 2

[test_dataset]
knowledge = ["./knowledge"]
count = 1
seed = 1234
model = "gemini:gemini-3.7-flash"
lladar create test-dataset --config .\config.toml

Paths written in the config file are relative to that file. Paths passed as CLI options are relative to the current directory. Explicit CLI options override the config. The config template is also protected from overwrite unless you pass --force.

Optional local policy

For a project-specific comparison, create a local TOML policy and select it with --policy .\policies\food-recommendation.toml. --policy can be repeated. When you specify any policies, that list is exact; add --policy builtin:general-social-context explicitly if you want the built-in policy too. See the policy example in the repository README.

What the configuration files and options do

PartMeaning
lladar create config --output .\config.tomlWrite an editable TOML template at config.toml. It does not generate questions.
schema_version = 2Version of the configuration file format, not the number of question groups.
[test_dataset]Section containing options for create test-dataset.
knowledge, count, seed, modelSaved values for the source paths, ready-group limit, ordering seed, and Akasha generation model.
lladar create test-dataset --config .\config.tomlRead those saved settings and generate a dataset. Set output in the TOML file or add --output to choose its filename; otherwise LLaDAR makes a collision-safe timestamped JSONL file.

4. Run the questions against your agent

Your target project needs its own Python environment with its dependencies installed. It must be different from LLaDAR's environment. The following example assumes your project is in my-agent and has my-agent/.venv:

lladar run-agent .\test-dataset.jsonl --project .\my-agent --target-python .\my-agent\.venv\Scripts\python.exe --no-graphify --output .\qa-results.jsonl

Without --entrypoint, LLaDAR inspects the project, proposes its public input/output interface, creates an adapter in a managed project copy, checks that the adapter can replay a question, and then runs each ready case in an isolated session. --no-graphify uses source inspection without the optional Graphify tool. If the project has several possible public interfaces, an interactive terminal asks you to choose one; a noninteractive run saves a continuation state that you can resume with lladar resume-agent RUN.

The answer file contains case IDs, exact questions, execution status and the agent's observed response. A successful adapter replay confirms that the connection worked; it does not establish that the answer was correct. Inspect the answers and the managed run directory under .lladar/runs/. Run only projects you trust: the managed copy is not an operating-system sandbox.

Provider and cost: dataset generation and automatic interface discovery use model calls. The target agent keeps its own model and credentials. Avoid publishing .env, datasets with private source text, answer files, traces or .lladar/.

Every argument in the run-agent example

PartMeaning
lladar run-agentRun the target Agent on usable cases and collect its actual answers.
.\test-dataset.jsonlRequired positional input: the dataset created in step 2. For a benchmark run, replace it with the bundle directory .\bbq-bundle.
--project .\my-agentRoot directory of your Agent's source project. Replace the example folder with a real project; LLaDAR inspects it and works in a managed copy.
--target-python .\my-agent\.venv\Scripts\python.exeThe Python executable in the target project's own environment, with that project's dependencies installed. It is separate from LLaDAR's Python. The file must exist.
--no-graphifySkip the optional Graphify code graph and use direct source inspection for interface discovery. The default is to try Graphify first.
--output .\qa-results.jsonlWrite one observed-answer record per line here. This file is the second positional input for lladar eval.

The runner also writes qa-results.jsonl.run.json beside the answer file. It records the dataset and answer paths, an answer-file hash, run identity, and available target-project information; benchmark runs additionally record source and bundle identity. Managed adapter and continuation state live under .lladar/runs/. If a run pauses for interface confirmation, RUN in lladar resume-agent RUN means the saved run directory path, not the answer file. An existing answer file is protected unless you explicitly use --force.

5. Evaluate the observed answers

For a dataset made with create test-dataset, join it with the answer file from run-agent:

lladar eval .\test-dataset.jsonl .\qa-results.jsonl --output .\evaluation.json

The evaluator matches cases by stable ID and writes a JSON evaluation artifact. It includes original-answer accuracy, scoring coverage, clarification and error outcomes, and differences between the original and its variants. The LLaDAR Bias-Free Score is a project-specific measure, not an official external benchmark score. The evaluator may call a model judge, so keep provider credentials available. Existing output artifacts are protected unless you explicitly use --force.

Inputs and files produced by eval

PartMeaning
.\test-dataset.jsonlFirst positional input: the question groups to score.
.\qa-results.jsonlSecond positional input: observed answers from run-agent. IDs connect answers to questions.
--output .\evaluation.jsonWrite the overall JSON evaluation here, including summary statistics and per-item outcomes.

This generated-dataset example also writes evaluation.items.jsonl next to evaluation.json, with one comparison per line. Pass evaluation.json, not the .items.jsonl file, to lladar report. Both files are protected from overwrite unless you add --force.

6. Example: import BBQ with lladar create test-dataset --convert-from (experimental)

This example imports the public BBQ repository. --convert-from also accepts a local source directory. The import agent reads source files and documented scoring rules without running programs from the source repository. This URL example needs network access and credentials for the selected Akasha model. Import coverage depends on the available source evidence.

lladar create test-dataset --convert-from https://github.com/nyu-mll/BBQ --output .\bbq-bundle

The bundle contains manifest.json, cases.jsonl, scoring-plan.json, a declarative converter, and a pinned source snapshot under evidence/source. Cases with supported rules are ready; unsupported cases and malformed source rows remain visible as unsupported and source_invalid. The specified output directory must not already exist.

Run and evaluate the imported cases

lladar run-agent .\bbq-bundle --project .\my-agent --target-python .\my-agent\.venv\Scripts\python.exe --no-graphify --output .\bbq-answers.jsonl
lladar eval .\bbq-bundle .\bbq-answers.jsonl --output .\bbq-evaluation.json

The runner executes ready cases and writes bbq-answers.jsonl.run.json beside the answers to identify the source revision and bundle. For a short trial, add --max-cases 20 to run-agent; unattempted ready cases appear as missing answers, so coverage is partial. Evaluation verifies saved hashes and the pinned converter before applying the saved scoring plan. Unsupported source metrics remain identified rather than being silently replaced.

Optional scoring rediscovery

To independently rediscover source scoring for a completed benchmark run, use the same source and its run record. This makes additional model calls and writes a new output directory:

lladar eval --from https://github.com/nyu-mll/BBQ --run .\bbq-answers.jsonl.run.json --output .\bbq-rediscovered-evaluation

Imported and rediscovered evaluations follow source-supported rules. They do not imply that your agent's generation settings reproduce the benchmark paper's conditions.

How the BBQ import command works

PartMeaning
lladar create test-datasetUse the same command family as knowledge-based generation, in import mode.
--convert-from https://github.com/nyu-mll/BBQRead the public BBQ repository as the benchmark source. A local directory can also be used. Import mode cannot be combined with --knowledge.
--output .\bbq-bundleCreate a new directory containing imported cases, scoring rules, and a pinned source snapshot. It is a directory, not a JSONL filename, and must not already exist.

In the benchmark runner command, .\bbq-bundle replaces the generated JSONL dataset, and --output .\bbq-answers.jsonl names the observed answers. Its other options have the same meanings as the table in step 4. The runner also creates bbq-answers.jsonl.run.json. In the next command, eval reads the bundle and answers and writes bbq-evaluation.json. You can add --max-cases 20 to the benchmark run-agent command for a 20-case trial; this option requires a benchmark bundle.

What the optional rediscovery command means

PartMeaning
--from https://github.com/nyu-mll/BBQIdentify the same benchmark source and independently rediscover scoring rules from its pinned snapshot.
--run .\bbq-answers.jsonl.run.jsonUse the completed benchmark run record to locate and verify its exact bundle and answers. Do not pass the answer JSONL here.
--output .\bbq-rediscovered-evaluationCreate a new directory with report.json, scoring-plan files, and audit evidence. Pass this directory to lladar report.

7. Write a Markdown report

Use lladar report after evaluation. It accepts a LLaDAR evaluation JSON file for a generated dataset or an imported benchmark, or the output directory created by eval --from. These commands use the files created in the examples above:

lladar report .\evaluation.json --output .\evaluation-report.md
lladar report .\bbq-evaluation.json --output .\bbq-report.md
lladar report .\bbq-rediscovered-evaluation --output .\bbq-rediscovered-report.md

The report is currently written in Traditional Chinese, regardless of this page's language. It includes a dataset introduction, test and evaluation methods, a description of the target project, results, and a per-question appendix. Statistics come from the evaluation artifact; an Akasha model writes explanatory text using the available evidence. Missing details are marked explicitly rather than guessed.

For .\bbq-report.md, LLaDAR also writes .\bbq-report.md.meta.json with provenance and report-generation details. An existing Markdown report or sidecar is protected unless you pass --force. If report writing fails, inspect .\bbq-report.md.failed.json; no partial Markdown report is published. Use --model to choose the writing model and --env-file to choose its credentials file. Review the report before sharing it because the appendix can contain source questions and your agent's answers.

Report command arguments

PartMeaning
.\evaluation.json or .\bbq-evaluation.jsonPositional input: a completed LLaDAR evaluation JSON file.
.\bbq-rediscovered-evaluationAlternative positional input: the directory produced by eval --from; LLaDAR reads its report.json.
--output .\bbq-report.mdRequired destination for the human-readable Markdown report. It does not change the input evaluation JSON.
--model MODEL, --env-file PATHOptional writing model and provider credential file. The report model explains saved evidence; it is not the target Agent's model.
--forceExplicitly replace an existing Markdown report and provenance sidecar.
