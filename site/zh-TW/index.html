操作說明

產生並評估 Agent 測試案例

從知識文件產生受控題組，或從外部 benchmark 匯入有來源依據的案例。用自己的 Agent 回答，再依據來源證據評估結果。

安裝產生題組重複使用設定執行 Agent評估答案外部 benchmark撰寫報告檔案對照指令索引

1. 安裝並準備模型服務

這份說明以目前儲存庫的原始碼為準，包含可能尚未進入已發布套件的本地變更。請使用 Python 3.11 或 3.12，從本專案的工作樹建立獨立的 LLaDAR 環境。以下指令適用於 PowerShell。

py -3.12 -m venv .venv-lladar
.\.venv-lladar\Scripts\Activate.ps1
python -m pip install -e .
lladar --help

LLaDAR 透過 Akasha 呼叫模型。請將所選模型服務需要的憑證放在本機 .env 或程序環境變數中。產生題組預設使用 gemini:gemini-3.7-flash；若要使用其他 Akasha 模型，可加上 --model。請勿把 .env 或執行資料上傳到公開儲存庫。

先看懂路徑與 --output

除非特別說明，範例都在本專案根目錄執行。在 PowerShell，.\ 代表目前目錄：.\my-agent 是專案資料夾，.\my-agent\.venv\Scripts\python.exe 是裡面的檔案。請把 my-agent 換成自己的專案路徑。緊接在指令後面的值稱為位置參數；--output PATH 這類項目是選項。這些本機路徑不會把檔案上傳到 GitHub Pages。

--output 指定該指令主要產物的儲存位置。依指令不同，它可以是檔案，也可以是新資料夾。範例中的 .\ 都以執行指令時的目錄為基準：

指令--output 代表其他產物
create configTOML 設定檔此範例沒有其他產物
create test-dataset --knowledgeJSONL 題組檔只有啟用追蹤或快取時才有相關檔案
create test-dataset --convert-from新的 benchmark 題組資料夾資料夾內含案例、評分規則與來源證據
run-agentJSONL 實際回答檔<回答檔>.run.json 與受管理的執行資料
eval DATASET ANSWERSJSON 評估檔一般產生的題組另有 <輸出檔主名>.items.jsonl
eval --from新的評估資料夾內含 report.json、評分方案與證據
reportMarkdown 報告檔<報告檔>.meta.json；撰寫失敗時為 <報告檔>.failed.json

.json 是一份 JSON 文件；.jsonl 每行是一筆 JSON；.toml 用於可編輯的設定；.md 是 Markdown 文字。安裝範例依序建立 .venv-lladar、啟用環境、用 pip install -e . 安裝目前工作樹，最後顯示 CLI 的第一層說明。待測專案的 .venv 與 .venv-lladar 是兩個不同環境。

2. 從知識文件產生測試題組

先建立 UTF-8 文件，例如 knowledge/plans.md：

# 會員方案
年滿 65 歲的顧客可使用 A 方案。
未滿 65 歲的顧客可使用 B 方案。

在包含 knowledge 目錄的位置執行：

lladar create test-dataset --knowledge .\knowledge --count 1 --seed 1234 --output .\test-dataset.jsonl

--knowledge 可接收一個或多個 .md、.txt 檔案或目錄；目錄會遞迴搜尋。正數 --count 是可用（ready）題組的上限；來源內容較少時，實際產出可能更少。跳過與重複的候選題不占額度。預設 --count 0 會處理所有候選內容。--seed 可固定候選順序。若明確指定的輸出檔已存在，指令不會覆寫。

一個題組包含：有來源依據的原始問題與參考答案、一題移除關鍵資訊的問題，以及一至四題加入受控情境提示的問題。在執行 Agent 前，變體的答案維持空值。實際題目會隨來源與模型輸出改變。

題組示意

  • 原始題：「70 歲的顧客適用哪個方案？」→ 參考答案：A 方案。
  • 移除關鍵資訊：「這位顧客適用哪個方案？」
  • 加入情境提示：「我的祖母適用哪個方案？」只有「祖母」這個提示，仍無法確定顧客年齡。

輸出為 UTF-8 JSONL，每行是一筆 JSON。可在 PowerShell 檢視第一筆：

Get-Content .\test-dataset.jsonl -TotalCount 1 | ConvertFrom-Json | Format-List

若省略 --output，LLaDAR 會在目前目錄建立不與現有檔名衝突的 test-dataset-YYYYMMDD-HHMMSS.jsonl。只測一個檔案時，可把 .\knowledge 改成 .\knowledge\plans.md。

產生題組指令逐項解釋

片段意思
lladar create test-dataset根據提供的知識文件產生 LLaDAR 測試問題。
--knowledge .\knowledge讀取本機 knowledge 目錄，遞迴尋找 .md 與 .txt。也可指定單一檔案或多個路徑。
--count 1最多產生一個可用的 ready 題組。預設 0 處理所有候選內容；來源不足時可能少於指定數量。
--seed 1234固定候選內容的選取順序；模型生成的題目文字仍可能變動。
--output .\test-dataset.jsonl將題組寫入這個 UTF-8 JSONL 檔。每行是一個題組，包含原題與變體。

knowledge/plans.md 是你提供的輸入文件，不是 LLaDAR 產物。test-dataset.jsonl 接著會交給 run-agent，再交給 eval。檢視指令中的 Get-Content -TotalCount 1 讀第一行，ConvertFrom-Json 解析 JSON，Format-List 列出欄位。

3. 保存可重用的設定

lladar create config --output .\config.toml

編輯 config.toml，例如：

schema_version = 2

[test_dataset]
knowledge = ["./knowledge"]
count = 1
seed = 1234
model = "gemini:gemini-3.7-flash"
lladar create test-dataset --config .\config.toml

設定檔內的路徑以設定檔所在目錄為基準；CLI 指定的路徑以目前工作目錄為基準。CLI 明確指定的選項優先於設定檔。若設定檔樣板已存在，必須明確加上 --force 才會覆寫。

選用自訂 policy

需要比較特定情境時，可以建立本機 TOML policy，再用 --policy .\policies\food-recommendation.toml 指定。--policy 可重複使用；一旦指定，所列項目就是完整選擇。若也要使用內建 policy，請明確加上 --policy builtin:general-social-context。格式範例見專案 README。

設定檔與指令各自的作用

片段意思
lladar create config --output .\config.toml建立可編輯的 TOML 設定樣板，不會產生測試題目。
schema_version = 2設定檔格式版本，不是要產生兩組題目。
[test_dataset]保存 create test-dataset 選項的區段。
knowledge、count、seed、model依序是來源路徑、可用題組上限、候選順序種子與 Akasha 產題模型。
lladar create test-dataset --config .\config.toml讀取保存的設定並產生題組。可在 TOML 設定 output，或於指令加上 --output 指定檔名；否則會建立避免撞名的時間戳記 JSONL 檔。

4. 用自己的 Agent 回答測試問題

目標專案必須有自己的 Python 環境，而且已安裝所需套件；該環境不能與 LLaDAR 共用。以下假設目標專案位於 my-agent，其虛擬環境位於 my-agent/.venv：

lladar run-agent .\test-dataset.jsonl --project .\my-agent --target-python .\my-agent\.venv\Scripts\python.exe --no-graphify --output .\qa-results.jsonl

未指定 --entrypoint 時，LLaDAR 會檢查專案，提出對外輸入與輸出的介面，在受管理的專案副本內建立 adapter，重播問題確認連接成功，接著以獨立工作階段執行每個可用案例。--no-graphify 會略過可選的 Graphify 工具，直接檢查原始碼。若專案有多個可能介面，互動終端機會要求選擇；非互動執行則會保存狀態，之後可用 lladar resume-agent RUN 繼續。

答案檔會保存案例 ID、原題、執行狀態與 Agent 的實際回覆。adapter 重播成功代表連接可執行，不代表答案正確。請檢視答案及 .lladar/runs/ 下的執行資料。受管理副本不是作業系統沙箱，僅執行你信任的專案。

模型與費用：產生題組及自動尋找介面都會呼叫模型。目標 Agent 保留自己的模型和憑證。請勿公開 .env、含私人來源文字的題組、答案檔、追蹤紀錄或 .lladar/。

run-agent 範例的每個引數

片段意思
lladar run-agent把可用案例交給待測 Agent，收集它實際回答的內容。
.\test-dataset.jsonl必填的位置參數：第 2 步產生的題組檔。執行 benchmark 時，改放資料夾 .\bbq-bundle。
--project .\my-agent待測 Agent 原始碼專案的根目錄。請換成自己的專案；LLaDAR 會檢查它，並在受管理的副本內工作。
--target-python .\my-agent\.venv\Scripts\python.exe待測專案自己的 Python 執行檔，該環境須已安裝專案依賴；它與 LLaDAR 的 Python 分開，而且檔案必須存在。
--no-graphify略過可選的 Graphify 程式碼圖，直接檢查原始碼尋找介面。預設會先嘗試 Graphify。
--output .\qa-results.jsonl將實際回答逐行寫入這個檔案。之後它是 lladar eval 的第二個位置參數。

Runner 也會在答案檔旁建立 qa-results.jsonl.run.json，記錄題組與答案路徑、答案檔雜湊、執行識別及可取得的待測專案資訊；benchmark 執行另記錄來源與題組識別。受管理的 adapter 與待續狀態放在 .lladar/runs/。若因介面選擇而暫停，lladar resume-agent RUN 的 RUN 是已保存的執行資料夾路徑，不是答案檔。既有答案檔只有明確加上 --force 才能覆寫。

5. 評估 Agent 的實際回答

對於 create test-dataset 產生的題組，搭配 run-agent 的答案檔執行：

lladar eval .\test-dataset.jsonl .\qa-results.jsonl --output .\evaluation.json

評估器依穩定案例 ID 對齊資料，輸出 JSON 評估結果，包含原題正確率、評分涵蓋率、澄清與錯誤狀態，以及原題和變體答案的差異。LLaDAR Bias-Free Score 是本專案自己的指標，並非外部 benchmark 的官方分數。評估可能呼叫模型裁判，請保留服務憑證。既有輸出檔受到保護，只有明確加入 --force 才會覆寫。

eval 讀取與產出的檔案

片段意思
.\test-dataset.jsonl第一個位置參數：待評分的測試題組。
.\qa-results.jsonl第二個位置參數：run-agent 取得的實際回答。以案例 ID 對應問題與答案。
--output .\evaluation.json輸出 JSON 評估結果，包含摘要統計與逐項結果。

此一般題組範例還會在 evaluation.json 旁建立 evaluation.items.jsonl，每行是一筆比較結果。交給 lladar report 的是 evaluation.json，不是 .items.jsonl。若任一輸出檔已存在，必須明確加入 --force 才會覆寫。

6. 範例：使用 lladar create test-dataset --convert-from 匯入 BBQ（實驗功能）

這個範例使用公開的 BBQ 儲存庫網址匯入資料；--convert-from 也接受本機來源目錄。匯入 Agent 會讀取來源檔案及文件化的評分規則，不會執行來源儲存庫的程式。使用網址需要網路連線與所選 Akasha 模型的憑證。匯入涵蓋率取決於來源提供的證據。

lladar create test-dataset --convert-from https://github.com/nyu-mll/BBQ --output .\bbq-bundle

輸出目錄包含 manifest.json、cases.jsonl、scoring-plan.json、宣告式轉換器，以及 evidence/source 下的固定來源快照。有來源支持評分規則的案例標為 ready；無法支持或格式錯誤的來源案例仍會以 unsupported、source_invalid 保留。明確指定的輸出目錄不得已存在。

執行並評估匯入案例

lladar run-agent .\bbq-bundle --project .\my-agent --target-python .\my-agent\.venv\Scripts\python.exe --no-graphify --output .\bbq-answers.jsonl
lladar eval .\bbq-bundle .\bbq-answers.jsonl --output .\bbq-evaluation.json

Runner 只執行 ready 案例，並在答案旁建立 bbq-answers.jsonl.run.json，記錄資料集與來源版本。若只想先小量試跑，可在 run-agent 加上 --max-cases 20；未執行的可用案例會列為缺少答案，因此評估涵蓋率只會是部分。評估前會核對已保存的雜湊與固定來源轉換器，再套用保存的評分計畫。無法重現的來源指標會明確列出。

選用：重新探索來源評分規則

若要對已完成的 benchmark 執行獨立探索，請使用同一來源與執行紀錄。此步驟會增加模型呼叫，並建立新的輸出目錄：

lladar eval --from https://github.com/nyu-mll/BBQ --run .\bbq-answers.jsonl.run.json --output .\bbq-rediscovered-evaluation

匯入與重新探索的評估都以來源支持的規則為界；結果不代表目標 Agent 的生成設定已重現原始研究條件。

BBQ 匯入指令逐項解釋

片段意思
lladar create test-dataset沿用題組指令，但切換為外部 benchmark 匯入模式。
--convert-from https://github.com/nyu-mll/BBQ以公開的 BBQ 儲存庫為來源；也可以改成一個本機資料夾。此匯入模式不能同時使用 --knowledge。
--output .\bbq-bundle建立包含匯入案例、評分規則與固定來源快照的新資料夾。這裡不是 JSONL 檔名，指定的資料夾不可已存在。

benchmark 的 run-agent 指令以 .\bbq-bundle 取代一般 JSONL 題組，--output .\bbq-answers.jsonl 指定回答檔；其他選項與第 4 步的表格相同。Runner 另建立 bbq-answers.jsonl.run.json。下一行 eval 讀取題組資料夾與回答，寫出 bbq-evaluation.json。小量試跑可在 benchmark 的 run-agent 加上 --max-cases 20，最多執行二十個案例；這個選項只適用 benchmark 題組。

選用的重新探索指令逐項解釋

片段意思
--from https://github.com/nyu-mll/BBQ指出同一個 benchmark 來源，依固定來源快照重新探索評分規則。
--run .\bbq-answers.jsonl.run.json使用完成執行時留下的紀錄，定位並核對當時的題組及答案；這裡不填答案 JSONL。
--output .\bbq-rediscovered-evaluation建立新資料夾，包含 report.json、評分方案檔與稽核證據。之後把這個資料夾交給 lladar report。

7. 產生 Markdown 評估報告

完成評估後使用 lladar report。輸入可以是一般題組或匯入 benchmark 的評估 JSON，也可以是 eval --from 建立的輸出目錄。以下指令接續前面的範例檔案：

lladar report .\evaluation.json --output .\evaluation-report.md
lladar report .\bbq-evaluation.json --output .\bbq-report.md
lladar report .\bbq-rediscovered-evaluation --output .\bbq-rediscovered-report.md

目前報告以繁體中文撰寫，包含資料介紹、測試與評估方法、待測專案說明、結果，以及逐題附錄。統計數值取自評估檔；Akasha 模型依據可取得的證據撰寫說明文字。缺少的資料會明確標示，不會臆測。

以 .\bbq-report.md 為例，LLaDAR 也會建立 .\bbq-report.md.meta.json，記錄來源及報告產生資訊。若 Markdown 報告或附帶檔案已存在，必須加入 --force 才能覆寫。若撰寫失敗，可檢查 .\bbq-report.md.failed.json；此時不會發布未完成的 Markdown 報告。可用 --model 指定撰寫模型、--env-file 指定憑證檔。分享前請檢查報告，逐題附錄可能包含來源題目與 Agent 回答。

報告指令的引數

片段意思
.\evaluation.json 或 .\bbq-evaluation.json位置參數：已完成的 LLaDAR JSON 評估檔。
.\bbq-rediscovered-evaluation另一種位置參數：eval --from 建立的資料夾；LLaDAR 會讀其中的 report.json。
--output .\bbq-report.md必填：可供人閱讀的 Markdown 報告位置；不會改動輸入的評估 JSON。
--model MODEL、--env-file PATH選用：撰寫說明的模型與服務憑證檔。報告模型負責解釋已保存的證據，不是待測 Agent 的模型。
--force明確允許覆寫既有的 Markdown 報告及來源紀錄附檔。
