選擇生成方法

Agent 依選定 Skill 從知識段落直接生成問答，或使用圖譜產生概念探針。圖譜不是必經流程；正式輸出前驗證最終候選，只有採用有效圖譜時才產生 .graph.json。

使用指南

建立測試資料

把你想讓 Agent 遵守的文件交給 LLaDAR，讓它產生一組可以實際拿去問 Agent 的題目。

這一步在做什麼？

測試資料不是隨便列幾個問題。主要 JSONL 的每一題包含問題、預期答案和待填入的實際回答；生成來源與方法記錄在旁邊的 sidecar。後面評估時，LLaDAR 會用這些內容判斷 Agent 的回答是不是真的出自知識文件裡的正確答案。這一步不等於完整檢查所有額外或捏造的內容。

基本用法

lladar create test-dataset --knowledge path/to/policy.md --output artifacts/dataset.jsonl
選項意思
--knowledge你要拿來出題的文件，例如政策、產品規格或內部說明。
--output要把產生的測試資料存到哪裡。

產生後先檢查什麼？

打開 dataset.jsonl，看看題目是不是在測真正關心的事情、預期答案是否合理，以及是否有足夠的來源說明可回頭確認。若文件本身不完整，題目也無法憑空補齊規則。

.generation.json 另存來源、選定 Skill、設定、跳過項目，以及 token_usage 的總量與各階段用量。用量也保存在工作階段檢查點和 dataset.jsonl.operation.md；還可以將保存的用量納入覆蓋率報告。

執行中查看 token 用量

從 v0.17.0 起，create test-dataset 會累計模型供應商回報的輸入與輸出 token。預設開啟 verbose，每次模型回應後以 [TOKENS] 更新累計數字，包含工具多輪呼叫與重試；等待回應時不會逐 token 更新。

lladar create test-dataset --knowledge policy/ --output dataset.jsonl --lang zh-TW --verbose --log logs/create.log

以下是示意數字，實際輸出還會附上時間：

[TOKENS] 階段=generation 累計輸入=4000 輸出=600 合計=4600 tokens；未回報用量的呼叫=0

LLaDAR 透過 Akasha／LangChain 讀取同一次模型回應附帶的 usage，不會為了統計再送一次提示詞，也不會增加 token 計數 API 呼叫。知識盤點、知識點對齊、出題、複查、覆蓋率審查與補題，實際執行時都會納入累計。

--no-verbose 隱藏即時更新，但仍保存用量。--resume 接續工作階段總量，作業報告另外列出本次執行新增的用量。供應商未回報的部分是未知，不代表零；舊紀錄也無法只靠文字重建用量。詳見用量欄位與統計限制。

想讓題目更符合團隊需求？

在出題階段放入自己的 SKILL.md，就能告訴 LLaDAR 要特別測哪些情境、不要問哪些內容，或採用團隊既有的題目格式。這適合把通用流程改成特定領域的測試流程。

探索 GitHub 資料集

lladar create test-dataset --from-github https://github.com/hsinmosyi/TWBias --count 20 --output dataset.jsonl

--knowledge 與 --from-github 擇一使用。Agent 自行找到公開文字資料集，並記錄答案依據。dataset.generation-report.md 涵蓋每道正式題目的來源摘錄、固定版本連結、轉換方式、模型檢查與限制；dataset.sources.json 保存原文。執行受測 Agent 前，請先檢閱生成判準。

範例

客服 Agent 範例使用 knowledge.md 中的退貨、出貨和退款規則來出題。接著會把這些題目交給既有 Agent 回答。

想測多輪對話？

若要觀察受測目標在多輪中的行為，請改看建立情境設定與多輪測試；這條流程不強制提供知識文件。
