作業結果報告

每次 CLI 主流程或 Skill 範本命令成功、失敗、取消或需要人工確認後，都自動嘗試產生 UTF-8 Markdown 報告。包含情境模式；help、版本查詢及 Python API 不產生此報告。

報告沿用 --lang，列出狀態、退出碼、時間、允許記錄的設定、輸入路徑、已知統計、產物、經清理的問題與下一步，區分新增、修改與既有檔案。本次失敗提供工作階段資訊時才附續跑指引。答案不正確是評估結果；執行或判斷錯誤才列為作業問題。

artifacts/evaluation.json 對應 artifacts/evaluation.json.operation.md；範本目錄 lladar-skills/eval 對應目錄旁的 lladar-skills/eval.operation.md。已有報告時使用 .operation-2.md、.operation-3.md，即使 --force 也保留歷次報告。輸出位置未解析或無法寫入時，退回原工作目錄的 .lladar/operation-reports/STAGE.operation.md。

不增加模型呼叫，也不改退出碼。--no-verbose 仍顯示報告位置；日誌啟用後也記入 --log。報告省略原始提示詞、回答、URL、憑證與任意例外訊息，搭配日誌及生成／評估證據使用。兩處都無法寫入時顯示警告；程序被強制終止時無法保證產生報告。

語言設定：--lang CODE

所有流程、Skill 範本命令與 help 都接受此選項。新工作預設 en，包含生成敘述。en、zh-TW、ja（別名 jp／Jp）、ko、zh-CN 提供完整介面、固定報告標題與離線範本資源。

其他有效代碼如 fr 交由模型理解，介面、固定標題與範本使用英文並顯示簡短提示。接受代碼不代表模型一定支援。代碼由英文字母與可選的連字號分隔英數子標籤組成。

lladar --lang ja --help
lladar create test-dataset --knowledge knowledge.md --lang zh-TW --output dataset.jsonl
lladar run-agent dataset.jsonl --project ../my-agent --lang zh-TW
lladar eval responses.jsonl --lang zh-TW
lladar report evaluation.json --lang ko
lladar create report-skill --lang zh-CN

保存的問題、受測回答、引文、ID、欄位名稱、精確 probe 與數值保留原值。網站答案擷取保留原回答；技術診斷與第三方追蹤可能保留原始語言。情境模式自由文字使用指定語言；此選項不增加受測 Agent 語言要求或評分條件。

下一步命令帶上語言。新階段省略時使用 en；--resume 省略語言時恢復保存值，明確指定時須相同。衝突會被拒絕；舊工作沒有語言紀錄時請使用原版本或建立新工作。Python 階段 API 接受 lang="ja"。紀錄區分 lang 與 ui_lang；範本的 language.json 另記錄 template_lang。

輸出路徑

所有主要階段都可省略 --output，也可指定資料夾或完整檔案路徑。 省略時輸出到目前工作目錄下的 runs/：資料集使用 test-dataset-YYYYMMDD-HHMMSS.jsonl， 其他階段依序使用 situation.json、responses.jsonl、evaluation.json、report.md。 指定 --output ./artifacts 時，預設檔名與附屬檔都放進 ./artifacts/。 既有資料夾、結尾分隔符號或沒有副檔名的新路徑視為資料夾； 既有檔案或有副檔名的新路徑視為檔案。含點號的新資料夾可寫成 ./results.v1/。 既有輸出仍需 --force。

每個階段成功後都會顯示工作摘要，列出輸出的絕對目錄、各檔案位置與內容簡述， 以及下一步命令或閱讀提示。--no-verbose 仍會顯示摘要，--log 也會同步保存。

共用選項

lladar --version 顯示已安裝的套件版本。在工作流程命令後或命令前加上 --log PATH，將終端輸出同步保存為新的 UTF-8 檔案。log 包含已輸出的進度、trace、摘要與已處理的錯誤，移除顏色控制碼；--no-verbose 會同時減少終端與 log 的詳細訊息。自動建立上層目錄；既有 log 會保留，--force 也不會覆寫。

lladar create test-dataset --knowledge policy/ --output dataset.jsonl --log logs/create.log

命令與參數參考

這裡列出目前 LLaDAR 的每個命令、參數、預設值和使用時機。想了解整體流程請看使用指南；需要查精確參數時看這一頁。

命令一覽

命令用途主要輸出
lladar create test-dataset從知識文件建立題目與預期答案。資料集 JSONL 與 .generation.json。
lladar create situation把觀察行為與停止條件編成可重用的情境設定；知識文件選填。情境 JSON。

plan

用自然語言描述想測的事情，讓 planner 釐清必要資訊，並將需求整理成可驗證的 PlanSpec。它是規劃器，不是執行器：不會呼叫受測目標、自動登入、保存憑證，也不會執行後續階段。

lladar plan [REQUIREMENT] [OPTIONS]

可以省略需求文字，直接啟動互動式規劃；若提供文字，會作為對話起點。

lladar plan "我想測客服是否依退款文件回答" --lang zh-TW
lladar plan --output runs/refund-plan --debug --log runs/refund-plan/plan.log
參數預設值用途
REQUIREMENT無測試目標的自然語言描述；可在互動對話中補充。
--output DIRECTORYruns/plan-YYYYMMDD-HHMMSS計畫包目錄；既有目錄不會覆寫。
--model MODEL模型 profile只指定規劃模型，不會自動指定後續階段的模型。
--env-file PATH.env規劃模型 provider 的環境檔。
--lang CODEen規劃對話、摘要與產物的語言。
--debug關閉顯示即時去敏化診斷事件。
--log PATH計畫目錄內的 plan.log另存結構化事件 log；既有 log 會保留。

計畫包通常包含 plan.md、plan.json、plan-events.jsonl 與 plan.log。ready 會另外提供 commands.ps1；blocked 或 failed 會提供 diagnostics.json。

ready 代表本機輸入、能力組合、命令參數與階段依賴通過靜態檢查，不代表受測 Agent 可連線或測試已成功。blocked 表示缺少必要輸入或能力；failed 表示規劃或產物處理發生錯誤。執行前請先閱讀計畫摘要與診斷。

資料集生成方法

選定 Skill 指引直接問答或選用圖譜。Python 可產生或修正候選，各交付方式都須通過最終驗證。JSONL 格式不變，.graph.json 為選用產物。

create test-dataset

從一或多個知識檔案或資料夾產生測試資料。

lladar create test-dataset (--knowledge PATH | --from-github URL) [OPTIONS]
參數預設值用途
--knowledge PATH未提供 --from-github 時必填；可重複知識檔案或資料夾；重複指定可合併多份輸入。
--from-github URL未提供 --knowledge 時必填探索公開 GitHub repo 的實際資料集，自動保存逐題查驗報告。
--skill DIRECTORY本機：knowledge-point-qa；GitHub：github-dataset一個包含 SKILL.md 的本機出題方法目錄。
--output PATH.產物目錄，會自動命名為 test-dataset-YYYYMMDD-HHMMSS.jsonl；若路徑以 .jsonl 結尾，則直接使用該檔名。
--count N0最多保留幾筆去重後資料；0 表示保留全部候選題目。
--seed SEED0固定候選題目的隨機排序。
--model MODELgemini:gemini-3.7-flash產生資料集使用的模型。
--env-file PATH.env提供給模型 provider 的環境檔。
--temperature TEMPERATURE0.0出題時的模型取樣溫度。
--max-input-tokens N所選模型設定覆寫模型設定的輸入 token 上限。
--max-output-tokens N所選模型設定覆寫模型設定的輸出 token 上限。
--auto-window-ratio RATIO所選模型設定覆寫自動 context window 的比例。
--force關閉允許覆寫既有輸出檔。
--verbose / --no-verbose開啟顯示或隱藏進度與出題 trace。
lladar create test-dataset --knowledge policy/ --knowledge faq.md --count 30 --seed 7 --output artifacts/dataset.jsonl

create situation

把觀察行為、停止規則、宣告的變化軸及固定評分方法編成情境 JSON；知識文件選填，與三欄單題 QA 資料集分開。

lladar create situation (--instructions TEXT | --instructions-file PATH) (--stop-criteria TEXT | --stop-criteria-file PATH) --max-turns N [--output PATH] [OPTIONS]
參數預設值用途
--instructions TEXT / --instructions-file PATH必須選一個整體生成、執行與預設評估指示，直接輸入或讀取 UTF-8 檔案；兩者互斥。舊 --observe／--observe-file 保留為別名。
--stop-criteria TEXT / --stop-criteria-file PATH必須選一個直接輸入語意停止規則，或從 UTF-8 檔案讀入；兩者互斥。
--max-turns N必填每個情境正整數的最多對答輪次。
--knowledge PATH無；可重複已存在的 .md 或 .txt 檔案；記錄路徑與雜湊，執行及評估時再次核對。
--output PATHsituation.json情境 JSON 路徑；已有檔案時須加 --force 才能覆寫。
--skill DIRECTORY內建 create-situation編製這份情境設定的本機 SKILL.md。
--model MODELgemini:gemini-3.7-flash編製情境使用的模型。
--env-file PATH.envprovider 的環境檔。
--force關閉覆寫已有的設定檔。
lladar create situation --instructions "資訊不足時請求訂單編號，避免編造狀態" --stop-criteria "完成追問回答或達最多輪次就停止" --max-turns 3 --output artifacts/situation.json

產物保存觀察和停止文字、知識雜湊、生成及執行方法、變化軸與評分規準。完整範例請看多輪情境指南。

run-agent

透過已檢查的專案或已校正的問答網頁執行 Agent，先驗證入口，再把回答填入新結果檔的 actual_response。

目標參數怎麼選？

單用 --project PATH 也可能足夠：LLaDAR 從原始碼與文件理解對外介面及啟動方式。必要執行環境設定完整時，可以在隔離的專案副本中啟動需要的服務，最後只關閉自己啟動的服務。啟動、驗證或 API 契約資訊不足時會要求補充。

要使用已啟動的測試服務時，才加上 --service-url URL。它提供的是基底位址，不是啟動指令，也不是 HTTP 方法、路徑、Payload 或回應格式；這些仍靠專案探索理解。LLaDAR 不會啟動或關閉該既有服務。參數名稱是 --service-url，不是 --service-api。

若只有正常問答網頁、沒有專案原始碼，改用 --page-url URL：瀏覽器登入、校正與錄製請求供重播，再由模型抽取回應文字。不能與 --project 或 --service-url 合用；未指定專案或網頁時預設檢查目前目錄。詳見三種方式的選擇指南。

lladar run-agent DATASET [OPTIONS]
lladar run-agent --situation-config PATH --num-scenarios N [OPTIONS]
參數預設值用途
DATASET單題模式必填輸入 JSONL；其中的 actual_response 必須是 null；使用 --situation-config 時省略。
--project PATH.要檢查並複製到隔離工作區的 Agent 專案；與 --page-url 二選一。
--page-url URL無正常問答頁面；固定引導登入、校正、授權與 MATCH，開瀏覽器前要求 stdin、stderr 為終端，不需互動旗標。
--output PATHresponses.jsonl主要 JSONL。單題模式另有 PATH.trials.jsonl 與 PATH.run.json；情境模式另有 PATH.scenarios.jsonl、PATH.turns.jsonl、PATH.calibration.json 與 PATH.run.json。
--skill DIRECTORY內建 run-agent-stability一個包含 SKILL.md 的本機排程方法目錄。
--situation-config PATH無使用固定的情境 JSON，省略 DATASET；不能與 --skill 合用。
--num-scenarios N無情境模式必填的正整數具體情境數。
--seed SEED0單題模式固定選題順序。
--model MODELgemini:gemini-3.8-flash專案 coding model；瀏覽器抽取預設 gemini:gemini-3.8-flash（目前支援 Gemini API）。
--env-file PATH.env提供給 coding model provider 與目標程式的環境檔；既有環境變數優先。
--target-python PATH單題：尋找 PROJECT/.venv；情境：專案 venv 或目前 Python目標專案使用的 Python 執行檔。
--timeout SECONDS3600（60 分鐘）每個 adapter、工具子程序或瀏覽器 request 的最長秒數；不會提高模型抽取的獨立限制。
--max-tool-calls N100每次探索或 adapter 修復最多可呼叫幾個工具。
--graphify / --no-graphify開啟開啟或關閉來源探索前的選用靜態程式碼圖。
--graphify-python PATH自動尋找既有 uv tool 環境含有 graphifyy 的 Python 執行檔。
--service-url URL無已啟動測試服務的 base URL；只適用 --project，不會理解任意 API URL。
--confirm-browser-run關閉只預先核准瀏覽器驗證題和已排程 request；不核准模型傳輸，也不能略過終端校正與 MATCH。
--allow-response-model-transfer關閉核准本次將真實回應內容傳至 --model；N 次試跑最多 N+2 次模型呼叫，每次 8,192 輸出 tokens、共用 60 分鐘。不核准網站請求，也不跳過獨立核對。
--max-input-tokens N / --max-output-tokens N所選模型的額度設定僅覆寫專案 auto-adapter 的探索、生成與修復額度，必須大於零；不改變受測 Agent 或瀏覽器擷取設定。預設 Gemini 3.8 Flash 為 1,048,576 input／65,536 output tokens。
--fresh-browser-profile關閉本次使用暫時的全新登入 profile，不重用該站既有 session。
--interactive / --no-interactive專案模式：只有 TTY 時開啟允許或禁止專案入口選擇提示；與 --page-url 合用會被拒絕，網站模式固定採終端引導流程。
--force關閉覆寫既有回答檔和附帶紀錄檔。
--verbose / --no-verbose開啟顯示或隱藏進度與 coding Agent trace。
lladar run-agent artifacts/dataset.jsonl --project path/to/agent --no-interactive --output artifacts/responses.jsonl
lladar run-agent artifacts/dataset.jsonl --project path/to/agent --service-url http://127.0.0.1:8000 --output artifacts/responses.jsonl
lladar run-agent artifacts/dataset.jsonl --page-url https://example.test/chat --output artifacts/responses.jsonl

瀏覽器啟動、首次導頁及重新導頁各自最多等 300 秒（5 分鐘），不受 --timeout 影響。網站回答仍預設等 60 分鐘，自動重播另受整輪剩餘期限約束。

僅保留模型直接抽取；預設 gemini:gemini-3.8-flash。一次 YES 同意所揭露的網站請求與真實回應外傳後，才讀取 GEMINI_API_KEY／GOOGLE_API_KEY。兩個核准旗標保留各自範圍，兩者都提供才免授權提示，仍不能跳過 MATCH。驗證題改在彩色 terminal（stderr）核對全文，不開 HTML 分頁；NO_COLOR 或 TERM=dumb 改用純文字。拒絕重新導向核對輸出，終端捲動紀錄可能留存內容；登入與擷取仍需瀏覽器。模型輸入上限為含封裝的 120 KiB UTF-8 JSON；超限不截斷、不重試。抽取合法不等於忠實或答案正確。詳見執行指南。

情境執行契約

專案可提供 lladar_session.py，或由 LLaDAR 在專案副本中產生候選程式。正式測試前必須通過同一 session 兩輪及新 session 隔離校準。指定的 --service-url 會透過 LLADAR_SERVICE_URL 傳入，adapter 必須呼叫真正的公開 API。情境模式不支援 --page-url。run JSON 記錄 adapter 雜湊、來源和錯誤。詳見校準流程。

lladar run-agent --situation-config artifacts/situation.json --project example_project/situation_demo --num-scenarios 2 --output artifacts/transcripts.jsonl

eval

用評估方法檢查已完成的回答，並由保存下來的逐題判斷計算彙總結果。

lladar eval RESPONSES [OPTIONS]
參數預設值用途
RESPONSES必填run-agent 產生的單題回答或情境對話 JSONL。
--output PATHevaluation.json要產生的評估 JSON。
--criteria TEXT無給內建方法的評估需求；與 --skill 互斥。
--skill DIRECTORY無包含標準與步驟的完整本機評估方法；也取代 typed／probe 預設評分。
--situation-config PATH無核對原始執行與設定雜湊，預設使用固定 rubric；--criteria 或 --skill 可替換評估，保留原始 config。
--model MODELgemini:gemini-2.5-flash評估 Agent 使用的模型。
--env-file PATH.env提供給評估 provider 的環境檔。
--strict關閉任一筆評估出錯就停止；不加時會把該筆記成 judge error，繼續其他資料。
--force關閉覆寫既有評估檔。
--max-input-tokens N / --max-output-tokens N所選模型 profile兩種模式的評估計畫與判斷所用的正整數 token 上限；保存於評估 JSON。
--verbose / --no-verbose開啟設定、逐題進度、模型等待提示、判斷狀態與耗時；--log 保存相同訊息。
lladar eval artifacts/responses.jsonl --strict --output artifacts/evaluation.json

兩者都不指定時沿用既有預設。結果與報告保存實際模式、準則全文與雜湊，或 Skill 來源與資源證據；只有正確性維度才產生正確率表。

lladar eval artifacts/responses.jsonl --criteria "觀察目標用詞；命中不等同偏見" --output artifacts/wording-evaluation.json

情境評估結果

情境評估保存有效性、行為判斷、引用的 turn ID 和確定性統計；失敗或無法判定的試次不計入觀察比例。

lladar eval artifacts/transcripts.jsonl --situation-config artifacts/situation.json --output artifacts/situation-evaluation.json

report

把評估輸出轉為不誇大結論、可回頭查的 Markdown 報告。

lladar report EVALUATION [OPTIONS]
參數預設值用途
EVALUATION必填eval 產生的評估 JSON。
--output PATHreport.md要產生的 Markdown 報告。
--skill DIRECTORY單題：內建 report-evidence-summary；情境：無本機報告方法；情境模式只增加敘述，不改已保存的判斷與統計。
--model MODELgemini:gemini-3.7-flash用 skill 撰寫摘要的模型；情境報告未指定 --skill 時不呼叫模型。
--env-file PATH.env提供給報告 provider 的環境檔。
--force關閉覆寫既有報告。
lladar report artifacts/evaluation.json --output artifacts/report.md
