# PRD：測試資料集生成流程層級

狀態為已同意開發。

`lladar create test-dataset --knowledge` 將提供三個流程層級。新工作預設按批次合併盤點與出題，使用者也可以加做選擇性覆核，或沿用 0.20.0 的完整分步流程。目標是減少重複送入原文和工具歷史的模型請求，並讓使用者從執行摘要和報告辨認覆核範圍。

## 命令列介面

新增 `--workflow-level {1,2,3}`。`--help` 列出層級、對應行為與預設值。`--count` 繼續控制去重後的全資料集題數上限，`0` 代表不限。`--skill` 繼續指定出題方法。

三個層級都支援 `--question-type {free,auto,single-choice,multiple-choice,ranking}`。`--question-type` 選擇作答形式，`--workflow-level` 選擇如何盤點、出題和覆核。本地文件的 CLI 新工作預設採用層級 1，包括使用自訂 Skill、啟用受控變體或明確指定題型時。

| 層級 | 生成流程 | 覆核範圍 |
|---|---|---|
| **1（預設）** | 每批合併盤點、批內整理、出題與覆蓋標記。 | 程式驗證引用、資料結構和對應關係。覆蓋聲明來自生成階段。 |
| **2** | 同層級 1，發現缺口時可按相關證據範圍補盤點或補題。 | 獨立覆審有疑義的題目對應，另抽查原文是否漏盤點。 |
| **3** | 沿用 0.20.0 的獨立盤點、語意整理、出題、原文覆核、整理與必要補題。 | 全部原文走獨立覆核，題目覆審沿用現行選擇及重用規則。 |

```powershell
lladar create test-dataset --knowledge ./knowledge --output ./runs/level-1.jsonl
lladar create test-dataset --knowledge ./knowledge --workflow-level 2 --question-type multiple-choice --output ./runs/level-2.jsonl
lladar create test-dataset --knowledge ./knowledge --workflow-level 3 --output ./runs/level-3.jsonl
```

## 合併盤點與出題

層級 1 和 2 的正常路徑以每批一次生成請求為目標。請求提供指派的原文、必要的跨批上下文與適用的 Skill 規則。模型一次提交該批知識點及其證據、可出題判定、候選問答與理由簡短的覆蓋對應。每個可驗證的事實都應保存在知識點清單，包括因題數上限或其他原因暫無題目的點。

程式按原始文件的字元位置驗證引用，檢查問答與知識點的連結，合併確定重複的項目，再依現行題目契約去重與選入資料集。正式覆蓋率依最終選入的題目及其對應計算。一題可覆蓋多個知識點，同一知識點也可對應多題。若批次提交不完整或引用驗證失敗，可保留已驗證的工作並重試受影響的批次。層級 1 的重試目的是完成有效交付，覆蓋缺口則直接記錄。

單選、複選和排序沿用現有題型契約，包含選項的來源依據、正確選項數或排序規則、答案格式與 sidecar 欄位。`auto` 可依來源產生合格的不同題型。明確指定題型時，候選缺少所需證據就依現行契約處理，輸出題目須符合指定題型。三個層級採相同驗證規則，各次執行的具體題目及覆蓋結果可能隨盤點與補題流程而異。

例如原文寫「一般商品可在 7 天內退貨，客製商品除外」。如果只輸出「一般商品的退貨期限是幾天？」這一題，盤點仍保留期限和例外兩個知識點，例外列為缺口。

## 層級 2 的覆核

- **覆審題目對應**。針對涵蓋部分事實、一題聲稱測到多個事實、合併後變動的知識點，以及準備從可出題分母排除的知識點。每次提供相關題目、預期答案、知識點和原文引文。
- **原文抽查**。由程式內建抽樣策略。使用者選層級 2 即可使用，抽查比例與選樣方式不由 Skill 或其他 CLI 引數設定。以原文批次為單位抽查 10%，向上取整，至少抽查一批。依原文中的條件、例外、否定或已記錄的跨批接續優先選樣。抽查名額至少兩批且同時有優先批次與一般批次時，兩類各抽至少一批，其餘依優先順序選樣。同類中的選樣可重現，續跑沿用已保存的抽樣名單。
- **獨立比對**。覆核者只讀抽中的原文及必要上下文，先自行找出事實，再由程式與第一次的盤點比對。記錄抽查批次、來源位置與發現的漏點。
- **局部補救**。抽查發現漏點時，先補進知識點清單。需要補題時只處理相關段落及必要上下文，並遵守 `--count`。完成後更新受影響的對應及缺口。

## 摘要、報告與續跑

CLI 執行摘要同時顯示層級數字和行為，例如「流程層級 2 · 合併生成、選擇性覆審與原文抽查」。`.generation.json` 記錄實際層級、原文覆核範圍與各覆蓋判定的來源。`lladar report` 讀取現有 sidecar 呈現已盤點知識點的覆蓋率、缺口，以及原文採生成時盤點、獨立抽查或全文獨立覆核。抽查覆核顯示抽查範圍。

正式 JSONL 沿用 `question`、`expected_answer`、`actual_response`。工作階段保存實際執行層級。`--resume` 省略引數時採用已保存的層級，指定不同值時提示層級不符。升級前建立的工作階段按層級 3 的相容路徑續跑，已完成的批次和用量統計可沿用。

## 範圍與相容規則

- 三層級設計以 `--knowledge` 文件出題為範圍。`--from-github` 沿用獨立的資料集探索、生成與審查流程。
- 需要讓自訂 Skill 直接操作分步工具、圖譜工具或提交自訂候選檔時，須明確指定 CLI 的 `--workflow-level 3`。直接呼叫 Python API 時，提供自訂 Skill 或啟用受控變體且省略 `workflow_level`，仍採用層級 3。
- 三個層級皆支援受控變體。層級 1、2 以合併批次接受的知識點驗證圖譜與配對，受控變體只收完整配對。執行摘要顯示實際層級。

## 驗收條件

1. 一般 `--knowledge` 新命令省略層級時採用層級 1，包含指定 `--skill` 的命令。`--help` 說明三個值，無效值在呼叫模型前提示。執行摘要、續跑資料與報告顯示一致的實際層級。
2. 層級 1 以單批短文件驗證正常情況只需一次生成請求，沒有後續模型覆核。原文包含期限與例外，輸出上限為一題時，兩個知識點都留在清單中，未覆蓋點仍列為缺口。
3. 層級 2 在無自訂設定時按內建規則抽查。單批來源覆核一批，20 批來源覆核兩批，有優先批次和一般批次時各選一批。續跑沿用已選批次。覆審能找出不成立的多點覆蓋聲明，並在抽查段落發現第一次完全漏掉的事實。補救只分派相關來源範圍，報告顯示實際覆核的範圍。
4. 層級 3 透過既有覆蓋、Skill、題型與續跑的相容測試，保留分步流程與既有輸出契約。舊工作階段可繼續完成。
5. 在同一模型、來源及出題需求下，對照短文件與多批次文件。使用人工核對的事實清單，比較漏點、有效題目和錯誤覆蓋對應。記錄模型呼叫數、輸入、快取輸入、輸出、重試、補題和總耗時，按適用費率比較總成本。比較合併與分步生成本身時，評估樣本採用相同的獨立覆核，避免把減少覆核的效果算成合併生成的收益。
6. 三個層級均接受五個 `--question-type` 值。用可形成完整選項與排序的來源驗證題型和答案格式，用證據不足的來源驗證指定題型的處理方式。省略層級的複選命令走層級 1，依同一題型契約產出資料集。

現行流程與輸出契約可參考[獨立知識點盤點與題目覆蓋率](PRD-knowledge-point-coverage.zh-TW.md)、[來源約束的題型化問答測試集](PRD-question-type-test-dataset.zh-TW.md)及[Skill 生成資料集](skill-generation.md)。
