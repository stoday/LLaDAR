# PRD：一次完整示範，由材料 Agent 與 adapter Agent 接通網站問答

## 1. 狀態與決策

- 日期：2026-10-13，Asia/Taipei。
- 版本：v1.2，需求基準；兩 Agent 原型曾在 EIP 真站沿用示範對話完成送題與收取，正式 CLI 與其他真網站仍需分別驗證。詳見[兩 Agent 原型驗證紀錄](browser-two-agent-eip-prototype-validation.zh-TW.md)。
- 入口：`lladar run-agent DATASET --page-url URL`。
- 使用者只需在同一次可見瀏覽器工作階段中，連續完成「登入 → 進入對話 → 輸入示範題 → 送出 → 等待完整回答」。程式全程錄製，完成後才啟動 Agent。
- 瀏覽器用於示範、蒐證及必要登入狀態保存；材料完整落盤後，預設由程式關閉本次錄製瀏覽器，再啟動 Agent。分析、adapter 試跑、驗證與正式執行不依賴原瀏覽器程序、頁面或活連線。
- adapter 根據保存的材料與狀態自行建立通訊、維持會話及收取回答。只有重錄、重新登入或必要人工核對時才按需開啟瀏覽器，完成後關閉；不以常駐可見或 headless 瀏覽器作為默認後援。
- 材料 Agent 負責目的性搜尋並選出可供程式生成的事件；adapter Agent 只依選定材料與真實試跑錯誤生成、提交、測試程式。失敗時保留累積材料，兩者再進入下一輪；第一次試跑成功就停止生成。
- adapter 是 Agent 生成的可執行程式產物，不只是人工填寫的 selector、固定請求模板或宿主預先寫好的網站 adapter。
- 宿主程式負責錄製、執行、驗證、派送與保存；不能用 Agent 自稱成功代替驗證。
- **不要求舊瀏覽器流程、旗標、adapter 格式、checkpoint 或模組相容。** 可刪除重建相關實作與測試；刪除範圍限於本功能及其直接依賴，不代表可移除其他 LLaDAR 功能或使用者資料。

本文件是 `--page-url` 重建的需求基準。與 [舊探索 PRD](PRD-browser-agent-discovery.zh-TW.md)、[固定擷取 PRD](PRD-browser-captured-api-evaluation.zh-TW.md)、[DOM fallback PRD](PRD-browser-dom-fallback.zh-TW.md) 衝突時，以本文件為準；舊文件及[既有驗證紀錄](browser-agent-discovery-validation.zh-TW.md)只作歷史證據，不能抵作新版驗收。`--project`、`--service-url`、`eval`、`report` 的功能不在重建範圍。

目標是對不同網站使用同一個錄製、查找、生成與測試流程。EIP 只是一個真站案例；正式邏輯不得以 EIP 網址、Direct Line 路徑、特定 token 欄位或固定答案格式決定要讀哪些材料、如何送題及如何收取回答。不同協定由 Agent 根據該站錄製證據生成 adapter；每站仍須獨立真站驗證，不能以 EIP 成功推論其他網站成功。

## 2. 問題與目標

目前工作樹的 `BrowserTarget.prepare()` 先要求使用者登入並返回終端，之後再進入手動校準。`GenericBrowserDriver` 已有網路及 DOM 變化記錄基礎，但部分 DOM 觀察以回合開始為條件。分段交接容易讓使用者不清楚何時輸入，並讓前置操作、會話初始化與問答記錄斷開。

新版將使用者示範視為一段連續證據，讓 Agent 查明操作、通訊、會話、回答與完成狀態的關係。錄製範圍必須涵蓋初次導頁至示範回答完成，不能只保留最後一張畫面或送題後的封包。

成功定義：

| 面向 | 要求 |
| --- | --- |
| 使用者體驗 | 正常首次接入只需啟動命令、確認執行範圍、完成一次連續示範，最後按 Enter 交接 |
| 有效送題 | adapter 確實把新問題送入使用者示範的目標服務 |
| 正確收取 | 保存本題完整回答原文，排除舊答案、其他會話、使用者訊息及背景推播 |
| 獨立執行 | 錄製瀏覽器關閉後，adapter 能自行建立 HTTP／SSE／WebSocket 通訊，送新問題並取得回答 |
| 可重複 | adapter 能連續處理不同問題，處理正常動態 ID、登入狀態更新與連線重建 |
| 自動化 | 合格後由程式執行 adapter；每題不必再啟動探索 Agent 或要求人工送題 |
| 可查證 | 每個候選、送題、完成判斷及回答都有對應的原始證據引用 |

「正確收取」不代表網站答對。拒答、不確定或錯誤答案均須忠實保存，不由接入 Agent 改寫。

## 3. 角色與工作流程

| 角色 | 責任 |
| --- | --- |
| 使用者 | 自行登入、處理 MFA／CAPTCHA、進入目標對話、示範一次問答，必要時核對完整原文 |
| 宿主程式 | 示範時開啟瀏覽器並錄製，保存必要狀態後關閉；提供受控通訊與試跑工具，驗證來源與完成，保存結果及用量 |
| 材料 Agent | 依示範標記、請求／連線與錯誤有目的地查找，累積選定事件 ID，寧可納入不確定線索 |
| adapter Agent | 收到選定材料與前版程式／錯誤後，生成並提交完整 `adapt(payload)`，立刻在真站試跑 |
| 生成的 adapter | 從保存狀態建立獨立連線、準備與更新會話、送題、收取、辨識本題、判斷完成、傳回原文與證據 |

標準流程：`執行範圍確認 → 開始錄製並開啟瀏覽器 → 一次人工示範 → 保存狀態並關閉瀏覽器 → 材料 Agent 選事件 → adapter Agent 寫程式並真站試跑 → 失敗則累積材料再修復／成功則停止生成 → 按會話政策驗證與正式執行 → 保存報告`。

關閉前先確認示範材料、必要狀態及獨立可見全文基準已落盤；若仍生成、材料未寫入或需要選定示範分頁，先在本次示範中補完。這項檢查證明材料已保存，不保證狀態必然可攜；是否足以重建須由關閉瀏覽器後的新題試跑證明。

內部可以有多個階段，但不可再要求使用者分別完成「登入交接、輸入探索、送題校準」三次手動操作。正常示範期間不中斷、不啟動探索 Agent 接管操作。示範題預先顯示，含可搜尋的唯一回合標記；不能來自正式資料集或要求網站回覆指定答案。

## 4. CLI 命令與 help 契約

以下為新版 CLI 契約。程式整合與真站驗收進度須以驗證紀錄區分；不保留舊旗標別名。

```powershell
# 第一次使用：完成一次問答示範後，程式保存狀態並關閉瀏覽器，adapter 獨立執行。
lladar run-agent dataset.jsonl --page-url "https://example.com/chat" --output responses.jsonl --lang zh-TW

# 示範題可自訂；程式會在顯示時加入本次唯一標記。
lladar run-agent dataset.jsonl --page-url "https://example.com/chat" --demo-question "請介紹這個服務可以協助的事項。" --output responses.jsonl --lang zh-TW

# 重用新版 adapter：預設不開瀏覽器；狀態失效且無法自動更新時才請你登入。
lladar run-agent dataset.jsonl --page-url "https://example.com/chat" --adapter ".lladar/browser-adapters/example/manifest.json" --output responses.jsonl --lang zh-TW

# 中斷後續作：只處理未提交題目，或收取已提交但尚未完成的回合。
lladar run-agent dataset.jsonl --page-url "https://example.com/chat" --output responses.jsonl --resume --lang zh-TW

# 明示沿用示範對話；回答可能受示範及試跑歷史影響。
lladar run-agent dataset.jsonl --page-url "https://example.com/chat" --conversation-policy demonstrated --output responses.jsonl --lang zh-TW
```

| 參數 | 新版說明與預設 |
| --- | --- |
| `DATASET` | 正式測試資料集；不交給探索 Agent，示範／驗證題不計入正式結果 |
| `--page-url URL` | 首次以可見瀏覽器完成示範並保存狀態，關閉後由材料 Agent 與 adapter Agent 生成並真站試跑 adapter；重用時不預先開啟瀏覽器 |
| `--demo-question TEXT` | 示範題正文；預設為詢問服務能力，顯示時附唯一標記。不得空白 |
| `--adapter PATH` | 重用新版 adapter manifest；重用仍需本次新題驗證，失效時由同一 Agent 修復 |
| `--conversation-policy independent\|continuous\|demonstrated` | 預設 `independent`，每個正式試次使用新對話；`continuous` 在一個新的正式對話累積歷史。明示 `demonstrated` 才可沿用示範對話，這模式以模型檢查回答是否具體、切題、合理，不要求字面相同，也不證明可建立新對話 |
| `--model MODEL` | Akasha 的探索／修復模型，與受測網站模型分開；實際模型 ID 與解析目的地須顯示 |
| `--output PATH` | 正式回答輸出；執行前顯示完整輸出及工作目錄位置 |
| `--resume` | 續作新版 session；不接受舊 checkpoint，也不重設已用額度 |
| `--extend-model-calls TOTAL` | 僅在 `--resume --page-url` 時明確提高同一工作階段的 Agent 模型呼叫總上限；保留既有用量與其他設定，顯示並記錄新上限 |
| `--fresh-browser-profile` | 示範／重新登入時使用獨立的未登入設定檔；預設可重用本機登入狀態。此旗標不要求重用／resume 主動開啟瀏覽器 |
| `--lang` | CLI 提示與報告語言；不翻譯網站答案、程式碼、證據或 schema keys |
| `--no-verbose` | 減少調查細節；必須保留人工指示、階段轉換、失敗原因及產物位置 |

`run-agent --help` 必須直接說明：「首次執行會開啟瀏覽器。請登入、進入對話頁、送出終端顯示的示範題，等待回答完成，再回終端按 Enter。程式保存記錄與必要登入狀態後會關閉這個瀏覽器；之後請等待 adapter 的生成、獨立連線驗證與正式執行。重用時通常不需要開啟瀏覽器。」不能只寫「guided workflow」或「calibration」。每個旗標都要寫用途、預設、何時需要及限制。

網站模式需要可互動終端；缺少 stdin／stderr TTY 時，在開啟瀏覽器及模型呼叫前停止並提示正確執行方式。模型設定、資料集及輸出位置無效時也先停止，避免使用者登入後才得知不能執行。

## 5. CLI 人工交接與完整提示範例

### 5.1 開始前，一次確認執行範圍

```text
[準備] 將開啟一個可見瀏覽器。你需要示範一次完整問答。
示範與狀態保存完成後，程式會關閉這個瀏覽器，後續由 adapter 獨立執行。
網站：<目標網站>
探索模型：<model ID>；模型目的地：<實際目的地>
正式試次：<N>；會話政策：每題使用新對話
輸出：<完整路徑>；記錄目錄：<完整路徑>
自動試跑、驗證與修復的時間／請求／模型額度：<實際設定>
程式會記錄頁面操作、DOM 變化、網路請求與回應，保存目標服務必要的登入／會話狀態，並將必要網站材料交給上述模型分析。
網站網路材料可能包含 Cookie、Authorization 與 session 資料；依本次授權範圍原樣處理。
輸入 YES 開始；輸入其他內容取消：
```

本次確認涵蓋錄製、模型分析、自動試跑、驗證、正式執行及額度內修復；不再拆成多個同義授權提示。若本次執行已經取得等價明確授權，不重複詢問；恢復時範圍或模型目的地變更才重新確認。

### 5.2 開始錄製，使用者連續操作

錄製器須先安裝完成，才導向目標 URL。終端先顯示以下內容，再等待使用者：

```text
[請操作瀏覽器] 瀏覽器已開啟，錄製已開始。
請在這個瀏覽器中依序完成：
1. 登入，完成網站要求的驗證；已登入可跳過。
2. 進入你要測試的服務，開啟一個新對話。
3. 複製下方完整示範題，輸入並送出。
4. 等待網站的完整回答顯示完畢。

示範題：
<完整正文及唯一標記>

過程中不用回終端，不用開 F12，也不用找 API 或輸入框位置。
完成後回到此終端按 Enter。請先不要自行關閉瀏覽器，程式會保存必要狀態後自動關閉；取消請按 Ctrl+C：
```

這段等待期間，錄製必須持續工作；不能用阻塞式終端輸入讓瀏覽器事件停止派送。使用者處理 MFA、原生對話框或新視窗時，程式維持記錄與等待，不自動關閉驗證對話框。終端不得插入 heartbeat 或背景輸出打斷使用者輸入。

### 5.3 示範完成後，程式接手

```text
[示範完成] 已記錄本次問題、送出事件、回答材料與畫面變化。
[保存] 正在保存記錄、必要登入／會話狀態及示範全文基準，請暫停操作瀏覽器。
[瀏覽器已關閉] 記錄已保存，後續不需要保持瀏覽器開啟。
[請等待] 材料 Agent 正在選擇錄製證據，adapter Agent 接著生成並測試程式；你目前不需要操作。
[分析] 正在追查示範題對應的請求、回答更新與可能的登入依賴。
[生成] 已產生 adapter v1，準備在沒有瀏覽器的情況下建立連線並自動試跑。
[驗證] 程式將送出新的驗證題。這些題目不計入正式資料集。
[驗證通過] 已確認瀏覽器關閉後仍可送新問題並取得本題完整回答。
[正式執行] adapter 正在獨立執行第 1／<N> 個試次；你目前不需要操作。
```

活動訊息須來自實際工具或狀態，不可在尚未讀取證據、生成或送題時顯示上述成功訊息。自動工作期間至少每 30 秒顯示實際階段、耗時、最近動作與剩餘額度；不得反覆只說「still working」。

### 5.4 只有具體缺口才再次請使用者操作

| 情況 | 必須顯示的指示 |
| --- | --- |
| 未發現示範題提交 | 「尚未找到示範題送出記錄。請回瀏覽器確認是否已送出；不要重複送題。確認後按 Enter 重新檢查。」 |
| 回答仍生成中 | 「回答尚未完成。請繼續等待網站；完整回答顯示後按 Enter。」 |
| 多個示範回合／分頁符合 | 列出與示範題相關的分頁標題、URL 與編號，請使用者選擇；不能默認最後分頁 |
| 無法建立獨立全文基準 | 示範期間先核對並保存同回合原文；新題驗證需要人工核對時，顯示「程式將暫時開啟網站供你核對剛才的回答」，找到同回合後逐字核對。符合輸入 `MATCH`，不符輸入 `MISMATCH`，尚未完成輸入 `WAIT`；核對完成後關閉核對瀏覽器 |
| 錄製缺漏，確實需要重錄 | 說明缺漏事件及為何無法修復，提示下一次示範題、重新錄製範圍與開始方式；不可讓 Agent 對殘缺材料無限猜測 |
| 登入逾期且無法自動更新 | 「自動派送已暫停，程式將開啟瀏覽器。請重新登入；完成後按 Enter。程式保存更新狀態後會關閉瀏覽器，先檢查未完成回合，再驗證 adapter；不會直接重送。」 |
| 無法重建獨立連線／會話 | 列出缺少的狀態、握手或會話步驟及實際錯誤；材料 Agent 補找、adapter Agent 修正。額度內仍不能解決則停止，不自動改成常駐瀏覽器執行 |
| 已送題但結果未知 | 顯示題目／試次識別及已送出證據，先嘗試取回該回合；無法確認時保存待處理狀態並停止 |

正常成功路徑不要求人工逐題核對；缺少可信全文基準時，人工核對是明示的例外。若正式題都需人工核對，報告須標示「需人工核對」，不能宣稱全自動完成。

核對瀏覽器只能查看 adapter 已獨立取得的同回合結果，不替它送題或供應維持連線所需的狀態。開啟核對頁面若造成狀態變更，須記錄並在核對瀏覽器關閉後重做獨立連線檢查。若 adapter 必須依賴持續核對才能運作，不算獨立執行通過。

## 6. 連續錄製與快照契約

| 類型 | 必須記錄的資訊 |
| --- | --- |
| 人工操作 | click、input／change、keydown、submit，操作目標引用及相關控制項狀態；能區分按 Enter 與點送出 |
| 頁面生命週期 | 初始導頁、重新載入、SPA 路由、frame 建立／導頁／移除、分頁及 popup、原生對話框的出現與結束 |
| DOM | 各文件初始基準、節點與文字／屬性變化、插入／移除、busy／disabled 等狀態，關鍵事件前後完整快照 |
| 網路 | HTTP 請求／回應與關聯、headers／body、串流有序片段、WebSocket 建連／傳送／接收／關閉，文字與二進位原文 |
| 資源 | 網站正常載入的客戶端腳本與可查閱資源，保留 URL、版本／hash 及來源 |
| 視覺輔助 | 導頁、提交與完成等關鍵時點的截圖；供診斷及必要視覺分析，不能單獨當作送題或完整性證明 |

每個事件有全域遞增序號、UTC 時間、單調時間、recording/page/frame/document ID、來源與材料引用；網路另外記錄 request／connection／message ID。操作及網路無法確定直接因果時，標示關聯候選，不把相近時間誤寫成確定因果。

從初次導頁就記錄，包括登入後既有連線的建立，避免到送題時才掛監聽。支援 popup 及跨 origin iframe 的宿主層觀察；頁面腳本無法存取的區域明列缺口。保留 UI、網路與原生瀏覽器觀察的交叉引用，不能把頁面腳本回報視為不可偽造證據。

採「完整事件時間線＋DOM 差異＋關鍵時點完整快照」，不在每次 mutation 都複製整頁。可合併重複更新，但必須保留順序、正文片段、最終狀態及合併範圍；串流中繼片段不得因去重而遺失。

錄製需串流落盤並可在 Ctrl+C 時保留已收集材料。大小／時間限制集中設定；顯示記錄事件數、bytes、缺漏與限制。達到上限或無法觀察時，標示明確缺口並停止或請求重錄，不能靜默截斷後宣稱完整。

初始提供 Agent 的資料是時間線索引、示範回合及前置依賴摘要；Agent 可依事件 ID 分頁讀取原文、快照、片段及資源。不得把所有原始材料一次塞進提示，也不得永久排除登入後初始化或前置操作。分頁材料須提供總長度、hash、範圍與完整性，片段不能假冒全文。

Playwright tracing 可作診斷產物，但不能單靠 tracing 保證錄到所有人工操作；實作須補充操作 listener、DOM 記錄與原生通訊觀察。參考 [Tracing](https://playwright.dev/python/docs/api/class-tracing)、[BrowserContext](https://playwright.dev/python/docs/api/class-browsercontext)、[Network](https://playwright.dev/python/docs/network)。

### 6.1 狀態保存與瀏覽器關閉

宿主在示範結束前保存經授權、與選定服務相關且可觀察的必要狀態，包括適用的 Cookie 屬性／期限、網站 token、CSRF 資料、localStorage／sessionStorage／IndexedDB 項目、conversation／session ID，以及初始化與連線握手材料。狀態保存須標記 origin、擷取時間、來源、版本／hash、可觀察的有效期及已知缺口；不是任意傾印整個設定檔或其他網站資料。

初始材料不一定能證明某個值必要，宿主可保存選定服務授權範圍內的狀態供 Agent 查閱。adapter manifest 再聲明實際需要的狀態引用與讀取用途。大型資料以引用／分頁提供，不要求使用者複製 Cookie 或貼入聊天。普通日誌不輸出狀態值。

保存內容是可序列化狀態與建立流程的證據，不能把原瀏覽器的 JavaScript heap、頁面物件、socket handle 或開啟中的 TCP／WebSocket 連線當成可攜產物。adapter 必須自行生成新的握手、訂閱、動態識別與必要前置呼叫；不能重播舊的單次 nonce 就宣稱已恢復 session。無法觀察或重建的依賴須明列，不能宣稱已保存「全部環境」。

材料原子保存並確認可讀後，關閉本次宿主管理的錄製瀏覽器及其分頁、context 與連線，保存關閉時間與結果；不關閉使用者其他瀏覽器。關閉失敗時明示，先完成清理再進入無瀏覽器試跑。新題驗證須在新的 adapter runtime／通訊連線執行，不能偷偷透過殘留的瀏覽器或遠端除錯連線操作。

參考 [Playwright 登入狀態保存](https://playwright.dev/python/docs/auth) 與 [WebSocket 握手協定](https://www.rfc-editor.org/rfc/rfc6455.html)。具體哪些狀態可移轉由各站試跑確認，不以某種 storage 匯出成功替代獨立執行驗證。

## 7. 兩個 Agent 與 adapter 契約

探索／修復透過 Akasha，分成材料 Agent 與 adapter Agent。宿主先建立有界錄製索引；材料 Agent 選定可能有用的事件及理由，並由宿主組成材料包。adapter Agent 只根據這份材料包提交新版 `adapt(payload)`，或具體指出缺少哪項觀測；它不能搜尋或分頁讀取錄製。宿主收到候選便執行本機預檢及真站試跑。失敗的結構化診斷與前版程式交回 adapter Agent 再提交，只有明確缺材料才回材料 Agent。每個 Agent 階段限一次模型呼叫；未選材、未提交或只回敘述文字即停止並回報。第一次真站試跑通過後立即停止生成。`--resume` 復用已選證據與候選。

宿主負責錄製索引、保存狀態、材料包及試跑；材料 Agent 使用選材工具，adapter Agent 使用提交程式／回報缺料工具。兩者均無直接瀏覽器控制工具；需重錄、登入更新或人工核對時，由宿主提示使用者並按需開啟瀏覽器。核心不得依網站 domain、框架名稱或固定 class 選擇特製方案。

adapter 必須包含可執行 source、manifest、依賴鎖定資訊、版本／hash、證據依據、必要狀態引用、連線建立／狀態更新策略、送題／收取方法、完成條件與失敗分類。宿主向程式提供受控的 HTTP／串流／WebSocket 通訊、授權狀態載入／保存與當輪證據介面；正式 runtime 不提供原瀏覽器物件、CDP 連線或 DOM 操作介面。

adapter 的邏輯能力：

- `send`：生成程式依錄製材料與保存狀態產生送題動作；必要的前置呼叫或 WebSocket 開連線可放在同一動作列表，且只能有一個攜帶當前問題的 `submit=true` 動作。宿主在真正送出前保存 intent。
- `receive`：生成程式讀取宿主已記錄的回應事件，判定是否完成並取出完整回答；尚未完成時可要求宿主繼續觀察。已送出的回合由宿主再次呼叫 `receive` 恢復，絕不重新呼叫 `send`。
- 宿主責任：執行 HTTP／WebSocket 動作、保存 Cookie 與連線狀態、管理逾時與會話政策，並從真實事件產生來源與完成引用。生成程式不得自行宣稱事件 ID，也不得把示範當下的 token 永久寫死在 source。

具體函式名稱與 schema 可由實作設計落實，但需有單一明確公開介面，不能讓 CLI 了解網站內部細節。生成程式須在可限制時間、資源及操作範圍的 runtime 試跑；不得修改 LLaDAR 核心或目標網站程式。

HTTP／REST、SSE、WebSocket 及其必要組合為獨立執行的接入方向，沒有固定協定嘗試順序。保存的 DOM 與操作記錄供調查、示範原文核對及理解網路事件使用，不作正式逐題瀏覽器送題／收取後援。Agent 可生成必要 codec、會話流程與答案定位／組裝程式，不受舊版「不能生成 parser」限制。這些程式只能忠實取得答案，不得代答、摘要、翻譯或補字。

若某站需要無法重建的瀏覽器執行環境，須列出具體依賴並標示「獨立 adapter 尚未接通」。保留瀏覽器或 DOM 路徑需另行修訂產品範圍，不能靜默降級或計為本版成功。

正式成功路徑以程式執行 adapter 為主，不要求每題重新呼叫探索 Agent。若候選確實需模型抽取，manifest 必須揭露每題的模型依賴、額外用量與驗證方式；它是有明示成本的可選能力，不引入第二個自治探索 Agent。預設目標是無逐題模型依賴的原文收取。

Agent 不可讀取 `expected_answer`、評分結果或未來正式題目。正式問題由宿主派送，預期答案只由後續評估使用。

## 8. 候選驗證與正式派送

1. 先檢查示範題、提交、頁面及完整回答材料是否可關聯，保存必要狀態與示範全文基準，再關閉錄製瀏覽器。確認錄製缺口；不能為殘缺示範直接啟動昂貴的無限探索。
2. 材料 Agent 選事件，adapter Agent 生成候選；宿主檢查介面、版本及可執行性。
3. 在新 adapter runtime 載入保存狀態，自行建立通訊，無瀏覽器自動試跑一題。失敗診斷與候選程式交給 adapter Agent 修正；只有它指出具體缺料，才交回材料 Agent；通過就停止生成。
4. 預設獨立模式在候選固定後送兩個不同的全新驗證題；題目在派送前不供候選生成。明示示範對話模式只要求通過一題真站新題試跑，報告其沿用對話的限制。
5. 每個驗證回合檢查實際提交、本題關聯、完整性與完成訊號。獨立模式使用可信本機 oracle、獨立取得的同回合原文基準，或按需開啟的核對瀏覽器；明示示範對話模式用 `akasha.ask` 判斷擷取答案是否具體、切題且合理，不以字面相同為門檻，但報告須標示這不是獨立全文核對。
6. 若無可信自動全文基準，依第 5.4 節人工核對。一旦修改候選，之前版本的資格失效，須重新試跑與新題驗證。
7. 按需開啟的核對／登入瀏覽器均已關閉，且獨立連線檢查通過後，保存合格 adapter，再按會話政策開始新的正式對話，無瀏覽器逐題執行。

驗證題是接入驗證，不考查網站答案內容正確性。只有傳輸終止、長時間沒更新、非空文字或固定延遲均不足以單獨證明本題完整。持續 SSE／WebSocket 不要求關閉，須使用經證明的應用層完成條件及本題關聯。

全文比較預設只允許已記錄的換行及呈現格式正規化；不得以語意相似代替原文一致，不能漏掉結尾、否定、數字或程式碼。正式每題仍檢查來源與完成；無可驗證的收取／完整性方法時，顯示具體缺口，不能填入成功回應。

示範、試跑、驗證與修復回合不得污染正式歷史。不能默默刪除使用者會話；無法透過獨立通訊建立要求的新對話時，停止並說明。正常首次接入只開啟一次錄製瀏覽器，材料保存後關閉；自動驗證與正式派送自行載入必要狀態並建立連線，不沿用原瀏覽器活連線。額外重錄、登入或核對需明示原因及使用者動作，結束後關閉。

## 9. 失敗、修復、取消與重用

每個試次至少區分 `not_submitted`、`submission_unknown`、`submitted`、`collecting`、`completed`、`failed`。宿主先存 intent，再提交並存 receipt，回答與證據成功落盤才標為完成。

- 正式題失效時暫停新題派送，保存本回合證據，由同一 Agent 修復；已有成功回答不可改寫。
- 未提交題目可在修復驗證後派送；已提交或提交未知則先恢復原回合，不自動重送。無法確認時停止並報告待處理狀態。
- 重複無進展達設定門檻、修復／模型／網站額度耗盡、來源不可確認或登入失效時，停止自動探索並給明確下一步。
- Ctrl+C 在人工示範、自動分析、送題與收取期間均有清楚取消訊息及產物位置；盡力停止後續操作、保存進度。突然斷電不保證最後未落盤事件存在。
- `--resume` 驗證新版 session 完整性與設定，恢復事件、候選及帳本，不重設用量或悄悄開始新 run。
- 連線中斷時，adapter 依已驗證的流程重建通訊並查詢原回合；重建不等於重送。服務允許的狀態更新由 adapter 保存，不能為每次斷線預設重開瀏覽器。
- 重用／resume 預設不開瀏覽器。必須比對程式／manifest hash、依賴、本站範圍與狀態，並做無瀏覽器新題驗證；登入狀態失效且無法自動更新時才按需重新登入。若需重新示範，只要求一次完整示範，不恢復舊三段流程。
- 舊產物不支援續作：提示「這是舊版瀏覽器產物，請啟動新版完整示範」；不覆寫或刪除舊資料。

## 10. 資料、授權與額度

延續已確定的網站原文授權方向：錄製的 URL、headers、Cookie／Authorization、body、JavaScript 與 binary 原文可交給設定模型，不新增私密值遮蔽／投影及阻擋機制。CLI 在開始前說明實際範圍及目的地，原文放於本機工作產物，普通進度與公開報告不複製這些內容。

Agent 不讀取 `.env`、provider key、完整瀏覽器設定檔檔案或任意其他網站 storage。為支援獨立 adapter，允許讀取宿主依第 6.1 節匯出的、經授權的選定服務必要狀態；這項保存與讀取納入開始前的一次範圍確認，不新增多重同義核准。登入、密碼／OTP／CAPTCHA 由使用者操作，DOM 密碼及 OTP 欄位不錄製輸入值。

時間、錄製大小、工具、模型、網站請求、試跑及修復額度集中設定，開始前顯示實際值。人工示範等待預設至少 3600 秒，獨立於自動探索限時；終端等待仍須維持錄製。人工錄製流量與自動執行流量分開計量，不能讓登入流量耗盡後續自動試跑額度。額度只能在新 run 重新計算，續作不得歸零。

不在本 PRD 散落硬編碼模型 token／封包大小；依選定模型與集中設定解析。每次模型呼叫前檢查材料大小與剩餘額度，分頁及摘要不能損害證據完整性。缺口報告包含限額類型及建議，不要求使用者提供敏感值。

## 11. 產物與完成報告

新版工作目錄至少包含：

```text
recording/          # 事件索引、原始材料、DOM 基準與差異、關鍵快照
state/              # 選定服務的必要登入／會話狀態、有效期、版本與更新紀錄
adapter/            # source、manifest、依賴、hash 與版本
validation/         # 瀏覽器關閉證據、獨立連線、每版試跑／新題驗證及全文核對
session.json        # 狀態、會話政策、設定與完整性資訊
ledger.json         # 模型／工具／網站／人工錄製／修復累積用量
discovery-report.md # 方法、證據、缺口與已驗證範圍
```

正式結果有穩定 item ID／trial ID 及回答原文，支持後續 `eval`；失敗答案為 `null`，不得用錯誤訊息或 Agent 猜測代替。示範及驗證答案另存，不計入正式結果。可重設瀏覽器產物格式，但不得破壞正式結果與後續評估的資料流。

結束時必須顯示：要求／完成／失敗／未知試次數、adapter 與正式結果位置、網站送題數及模型用量、瀏覽器關閉與獨立執行驗證結果、額外開啟瀏覽器的原因／次數、成功／部分完成／停止原因、是否需要使用者操作與可用續作命令。只有全數正式試次完成才顯示「正式執行完成」。不能把生成 adapter、通過本機測試或一題成功說成全站接通。

## 12. 驗收條件

| ID | 必須通過的情境 |
| --- | --- |
| SD-01 | 真可見瀏覽器從初次導頁開始錄製；首次接入只有一次連續人工示範交接，材料與必要狀態保存後關閉 |
| SD-02 | 示範等待期間 HTTP、串流、WebSocket、DOM 與人工操作持續記錄，終端輸入不被背景訊息打斷 |
| SD-03 | 登入、popup、iframe、SPA 導頁、既有長連線與 rerender 的順序及引用可查證；缺漏明列 |
| SD-04 | 單一真 Akasha Agent 根據錄製材料產生新的可執行 adapter；宿主沒有預填網站方案 |
| SD-05 | 原瀏覽器已關閉時，自動試跑及兩個不同新題驗證通過，第二題不取到舊答案；改版後重做資格驗證 |
| SD-06 | 持續 SSE／WebSocket 不必關閉也能辨識本題完成；二進位方法有真實解碼及完整性證據 |
| SD-07 | 尾段漏收、提前判完成、背景推播、其他會話答案及只返回片段均被拒絕 |
| SD-08 | 獨立全文基準有效；無基準時 CLI 明確要求 MATCH／MISMATCH／WAIT，不以相似度放行 |
| SD-09 | 正式會話不混入示範／試跑歷史；兩種會話政策行為符合 CLI 說明 |
| SD-10 | 正式題失效交回同一 Agent 修復；未知／已提交題不盲目重送，成功結果不改寫 |
| SD-11 | 取消、逾期、限額及 resume 保存狀態與用量；舊產物明確拒絕且不被刪除 |
| SD-12 | `--help`、所有人工提示、等待訊息與完成報告可清楚回答「我現在要做什麼」；語系同步 |
| SD-13 | 錄製限制與材料分頁不靜默截斷；Agent 可追查示範以前的初始化依賴 |
| SD-14 | adapter 在新 runtime 重載保存狀態，不開瀏覽器而通過新題驗證，獨立執行至少五個正式試次 |
| SD-15 | 保存狀態有來源、有效期與缺口；不能以舊 socket handle、單次 nonce 或殘留 CDP 連線冒充獨立重建 |
| SD-16 | 連線重建及服務正常輪替 Cookie／token 後可繼續執行；無法自動更新時提示重新登入，保存後關閉瀏覽器並重新驗證 |
| SD-17 | 原文核對需要瀏覽器時按需開啟，核對後關閉；核對不替 adapter 送題或維持連線，缺少獨立全文基準明示 |
| SD-18 | 無法重建會話時列出具體依賴並停止，不自動退回可見／headless 常駐瀏覽器或 DOM 派送 |

必要目標為 ChatGPT、Gemini、EIP 與原生 Streamlit 問答頁，各站分別記錄實際模型／版本、示範、狀態保存、瀏覽器關閉、獨立握手／會話建立、送題／收取方法、完成與核對證據、至少五個無瀏覽器正式試次及 adapter 重用結果。無法離開瀏覽器執行的網站標示未通過。不能替原生 Streamlit 增加 REST 包裝來冒充原生接入，也不能把使用 Gemini 模型的本機服務當成 Gemini 網站。

驗證層級分列：離線工具／資料流、真瀏覽器＋本機服務、真 Akasha Agent＋隨機本機服務、真網站新題驗證、真網站正式資料集。Skipped、沒有登入權限或未完成網站驗收均標示未完成，不以較低層證據抵代。

## 13. 重建與交付順序

1. 定義新版錄製、狀態匯出與獨立 adapter 公開介面、session 狀態、CLI 名稱及提示；移除與新契約衝突的舊規則。
2. 完成可見瀏覽器一次連續示範、事件與必要狀態落盤及瀏覽器關閉，先驗證終端等待、popup／frame 與持續連線，不提前宣稱接通。
3. 接入宿主錄製索引、材料 Agent 選定工具及 adapter Agent 程式提交工具，由宿主執行無瀏覽器試跑、驗證及正式派送。
4. 完成狀態更新、連線重建、失敗修復、未知提交恢復、重用與取消，驗證三種會話政策及按需登入／核對。
5. 清理被替代的瀏覽器模組、舊旗標／別名、測試與矛盾文件；保留其他模式及使用者產物。
6. 執行 SD 驗收及四站實測，更新 README、CLI help、語系、操作文件與新版驗證報告。

本文件為需求基準；使用者已於同日確認 CLI、Agent 記錄工具及獨立 adapter 三個測試介面，授權依 TDD 實作。進度見[新版驗證紀錄](browser-single-demonstration-validation.zh-TW.md)，尚未完成的四站驗收不能寫成既成事實。

## 14. 已固定的搜尋與工具契約

宿主先依示範標記、request／connection 關聯與事件種類，建立有界錄製索引。材料 Agent 的唯一工具是 `select_material`；它從索引選取事件並提供理由。宿主把選取事件的有界內容、理由、前版程式及試跑診斷組成材料包。adapter Agent 只有 `submit_adapter` 與 `request_more_material`，沒有錄製搜尋、讀取或真站操作工具。宿主在 `submit_adapter` 後立即執行 `test_live`，失敗才啟動下一次生成呼叫。

錄製事件以本機 SQLite 保存；依序號、種類、page／frame／turn、request／connection 與單調時間查詢。先搜尋唯一示範標記、沿相關請求或連線追查回答，再按需往前查初始化，不把整份記錄讀進模型。查詢只返回事件 metadata、URL、大小、hash 及引用；游標 `after` 為不包含該序號的續頁位置。

錄製儲存層的 `read_material(event_id, offset, limit)` 按字元範圍返回事件 JSON 原文，包含總字元／bytes、hash、已讀範圍及 `next_offset`；此介面不配給 adapter Agent。只有從零開始且涵蓋全文才標 `complete=true`。binary 原文以 Base64 保存，可用解碼後的 UTF-8 文字定位示範標記；該搜尋解碼不能代替協定解碼或來源驗證。

adapter 定義 `adapt(payload)`，由純 Monty VM 為 `send`／`receive` 兩種階段生成操作計畫，宿主執行。動作必須有 `kind`，合法值為 `http`、`ws_open`、`ws_send`、`ws_receive`；只有攜帶本題內容的動作可標 `submit=true`。`receive` 完成時只需提供 `answer`；宿主從實際記錄產生 `source_refs` 與 `completion_refs`。宿主另提供原文、URL 編碼、JSON 跳脫與 Base64 的題目形式，供生成程式依實際錄製格式替換示範題；需核對網站原文時，可另提供已授權網站內的 `reference_url`。

三個不同、已由可信 oracle／人工核對全文的回合，可資格化獨立宿主原生 JSON reader。正式回合須有本題提交關聯、完整 JSON 原文及自然 HTTP 結束，才可依已資格化的唯一答案位置逐字核對；串流或未知 binary 不因 JSON reader 成功而自動資格化。
