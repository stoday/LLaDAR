# PRD：各階段共用的 `--lang` 語言設定

狀態：已實作並通過離線驗證；尚未執行五語真實模型驗證

日期：2026-10-12

適用流程：create → run-agent → eval → report，以及 Skill 範本建立

## 問題與目標

目前 LLaDAR 沒有統一的語言參數。CLI 說明、進度、完成摘要、錯誤與續跑指引多為英文，部分互動選單則使用中文；模型生成內容依 prompt 與 Skill 而異，報告還包含程式直接輸出的固定標題。

使用者應能在每個階段透過同一個 `--lang`，設定操作介面與 LLaDAR 生成內容的語言。只在 prompt 末端加入「使用語言：en」不足以涵蓋程式直接輸出的文字，也沒有說明哪些資料必須保留原值。

本規格定義語言設定的使用方式、作用範圍、資料保護邊界、續跑行為與驗收條件。實作時仍須遵守既有階段的資料、證據與確定性計算契約。

## 使用者情境

1. 使用者以繁體中文執行完整流程，從 help、互動選擇到報告都能讀到一致的說明。
2. 使用者以英文生成測試資料與評估報告，供不同語言的團隊閱讀。
3. 使用者中斷工作後續跑，原有語言設定會恢復，不會在同一份產出混入不同語言。
4. 使用者建立繁體中文 Skill 範本，不需要模型或 API key，就能取得可直接使用的本機範本與作者指南。
5. 使用者切換操作語言時，既有問題、受測 Agent 回答與來源引文不會被偷偷改寫。

## CLI 契約

### 支援值與預設

模型生成語言不採固定白名單；程式直接顯示的文字與離線範本則需要已維護的翻譯資源。兩者由同一個 `--lang` 選擇，不增加其他語言旗標。

| 代碼 | 語言 | CLI、固定文件文字與離線範本 |
| --- | --- | --- |
| `en` | 英文 | 完整支援 |
| `zh-TW` | 繁體中文 | 完整支援 |
| `ja` | 日文 | 完整支援；接受 `jp`／`Jp` 作為別名 |
| `ko` | 韓文 | 完整支援 |
| `zh-CN` | 簡體中文 | 完整支援 |
| 其他格式有效的代碼，例如 `fr`、`de`、`es` | 交由所選模型理解 | 使用英文資源，並說明此設定 |

- 第一版完整維護上表的五種語言，其他代碼仍可用於模型生成，不以「未提供介面翻譯」為理由拒絕。
- 語言代碼以不區分大小寫方式辨識。已知值儲存為上表的標準寫法，`jp` 正規化為 `ja`；其他值以小寫形式保存與比對。
- 未列入完整支援的代碼，模型收到該代碼的生成語言要求；CLI、固定報告標題與範本使用英文，每次呼叫以一則簡短提示說明。該提示亦適用於 help 與 `--no-verbose`，並遵守既有 `--log` 行為。
- 任意代碼並不表示任意模型都能理解或穩定使用該語言；文件不得宣稱其他代碼已獲完整翻譯或模型品質驗證。
- 新工作省略 `--lang` 時使用 `en`。這是本規格新增的統一預設，模型生成內容也使用英文；實作發布時須說明這可能改變既有來源語言跟隨行為。
- 第一版不提供自動偵測、作業系統語系推導、環境變數設定或額外的介面／內容語言旗標。
- 空值或格式無效的代碼必須在模型呼叫、受測 Agent 執行與產出寫入之前被拒絕。第一版接受格式為 `[A-Za-z]{2,8}(?:-[A-Za-z0-9]{1,8})*` 的代碼，不接受空白、句子或控制字元；這是程式的代碼格式檢查，不代表已驗證語言代碼存在或模型支援。無法解析語言時，以英文顯示錯誤與範例。

### 命令位置與範圍

`--lang` 可放在主命令、`create` 群組或最終子命令的選項位置，讓頂層 help 與各階段 help 都能切換語言。以下為實作完成後的使用方式：

```powershell
lladar --lang zh-TW --help
lladar create --lang zh-TW --help
lladar create test-dataset --lang zh-TW --help
lladar create test-dataset --knowledge .\knowledge.md --lang zh-TW
lladar create situation --instructions "測試客服回覆" --stop-criteria "客服已完成回覆" --max-turns 5 --lang zh-TW
lladar run-agent .\test-dataset.jsonl --project .\target-project --lang zh-TW
lladar eval .\responses.jsonl --lang zh-TW
lladar report .\evaluation.json --lang zh-TW
lladar create report-skill --lang zh-TW
lladar report .\evaluation.json --lang ja
lladar report .\evaluation.json --lang ko
lladar report .\evaluation.json --lang zh-CN
lladar report .\evaluation.json --lang fr
```

- 主流程五個階段，以及五個 `create <stage>-skill` 命令都接受此選項。
- 同一次呼叫多次指定相同的正規化值可接受；不同值須報錯，不依參數位置默默覆蓋。
- `--help` 使用該次呼叫的語言，不需要 provider、登入或產出檔案。
- `--lang` 不改變 `--verbose`、`--no-verbose`、`--log`、輸出路徑或覆寫規則。
- Python API 使用對應的 `lang` 關鍵字參數與相同正規化規則；CLI 與 API 共用語言政策。

## 各階段內容範圍

| 階段 | 使用指定語言的 LLaDAR 內容 | 必須保留的既有資料 |
| --- | --- | --- |
| `create test-dataset` | 新生成的問題、預期答案、選項、說明、生成證據摘要與模型檢查理由 | 原始來源、逐字引文、引用位置、ID、選項代碼與結構化契約 |
| `create situation` | 新生成的情境敘述、對話指引與人類可讀說明 | 使用者原始 instructions／observe／stop criteria、來源證據與機器可讀設定 |
| `run-agent` | 操作提示、介面探索的標籤與理由、排程說明，以及 LLaDAR 情境測試器新撰寫的自由對話文字 | 已存問題、固定 probe、受測 Agent 輸出、連線與傳輸契約 |
| `eval` | 模型生成的評估理由、證據說明與限制說明 | 待評估問答／逐字稿、評估方法、判定代碼、分數與統計 |
| `report` | 報告正文、標題、表格欄名、指標說明與限制說明 | 數值、引用 ID、來源引文，以及作為證據呈現的既有問答／逐字稿 |
| `create <stage>-skill` | 新建立範本的說明、執行指引、描述文字與 `AUTHORING.md` | Skill 名稱與 frontmatter key、工具名稱、參數 key、程式碼與結構化範例的契約 |

補充規則：

- 將來源內容轉述為指定語言時，仍須受來源支持，不得新增事實、刪除否定或改變數量、條件與回答意義。
- `run-agent --lang` 不會在送往受測 Agent 的既有問題末端加上語言要求，也不修改受測 Agent 的 system prompt。
- 情境模式中新撰寫的自由對話可依指定語言生成，但不得翻譯或改寫固定校準 token、精確匹配 probe 與設定中要求逐字送出的文字。此模式的生成語言須記錄為測試條件。
- `eval --lang` 只改變說明語言，不新增「回答必須使用某語言」的評分要求；若要評估語言遵循，須由測試資料或評估條件明確定義。
- `report --lang zh-TW` 可針對英文的 evaluation 生成繁體中文報告；輸入證據維持原值，不回寫或重新評估輸入。
- 不把既有資料中的所有字串當成可翻譯欄位；欄位需由各階段明確列為新生成的敘述內容。

## 操作與顯示範圍

| 位置 | 納入語言設定的文字 |
| --- | --- |
| Help | 命令用途、參數說明、分組標題、範例的說明文字、argparse 的用法與錯誤提示 |
| 進度 | 工作階段、等待／仍在執行訊息、處理項目、完成摘要與時間說明 |
| 互動 | 功能與介面選擇、輸入要求、補充需求、無效選擇、登入或人工操作交接指引 |
| 錯誤與警告 | LLaDAR 自有的錯誤理由、操作建議、取消、設定或 checkpoint 不相容提示 |
| 完成摘要 | 工作用途、輸出目錄、各檔案說明、下一步命令與閱讀指引 |
| 中斷續跑 | 工作階段用途、恢復步驟、必要輸入與最後成功保存狀態的說明 |
| 產出文件 | 報告與證據摘要的固定標題、表格欄名、註解，以及範本作者指南 |
| 文字日誌 | 與當次終端相同語言的人類可讀訊息，保留既有輸出鏡像行為 |

- 命令、旗標、路徑、URL、模型代碼、鍵盤快捷鍵、工具名稱與機器可讀事件標記保持不變。
- 狀態代碼保持原值；若需要中文說明，另提供翻譯標籤，不以中文取代儲存的狀態值。
- 第三方錯誤、遠端回應與技術診斷細節保留原文；LLaDAR 提供指定語言的外層說明與常見操作錯誤翻譯。既有隱私與錯誤清理規則持續適用。
- 即使使用 `--no-verbose`，必要互動、錯誤與完成摘要仍依指定語言呈現。
- 本機瀏覽器操作指引可切換語言；受測網站本身的介面與第三方登入頁不由此參數控制。

## 模型與 Skill 的語言規則

所有 LLaDAR 控制的模型呼叫，包含中間生成、探索、校驗、修正與重試，都使用同一份語言政策。不得只修改最終回答 prompt。

模型指示須明確說出語言名稱與作用範圍，例如：

```text
Write all newly generated human-readable content in Traditional Chinese.
Keep JSON keys, IDs, enum values, tool names, code, and verbatim source quotes unchanged.
Do not translate saved target-agent responses or change evidence, scoring rules, or numeric results.
```

- 語言指示統一加入 LLaDAR 控制的 system prompt；若某 provider 不提供 system 欄位，使用其等效指示介面。
- 原文答案擷取模型是保留資料的例外：其任務是逐字還原網站回答，不加入生成語言指示，也不翻譯答案。情境 provider 的結構化請求會附上等效語言政策，方便注入的 provider 使用相同規則。
- 已知代碼映射為明確語言名稱：English、Traditional Chinese、Japanese、Korean、Simplified Chinese。其他代碼則使用「Write newly generated human-readable content in the language identified by this code: fr.」等明確指示，不必為每種生成語言新增程式分支或翻譯字典。
- 不直接拼接未檢查的原始引數；先驗證格式並正規化。若模型無法理解代碼，不偷偷改成其他生成語言，也不增加額外翻譯模型呼叫；一般生成失敗依既有階段錯誤處理。
- 語言政策位於可信指示區域，來源、遠端內容與受測 Agent 回答仍作為不可信資料處理。
- 使用者傳入的自訂 Skill 不會被改寫。對新生成敘述的語言要求由當次 `--lang` 決定，優先於 Skill 的一般呈現語言偏好；不因此改變 Skill 的方法、證據或結構契約。
- Skill 或來源若要求逐字引用、精確字串或程式碼輸出，依保留原值規則處理，不以全面翻譯破壞契約。
- 語言指示是模型要求，不保證每次生成都完全遵循。第一版不增加額外模型呼叫、整份輸出自動翻譯或單靠中文字元比例的語言判定；以既有驗證與實際樣本確認效果，保留專有名詞與原始證據混用的合理情況。
- 對沒有模型呼叫的確定性路徑，直接套用顯示翻譯，不為翻譯新增模型呼叫。

## 下一步命令、紀錄與續跑

### 跨階段操作

- 完成摘要印出的下一步命令與 Skill 範本使用命令必須帶上正規化的 `--lang`。
- 不同階段可各自指定不同語言；例如中文資料可以生成英文報告。
- 新階段若省略 `--lang`，使用 `en`，不隱含繼承輸入檔的生成語言。印出的下一步命令負責明確傳遞目前選擇。

### 工作紀錄

- 在既有工作階段設定中記錄有效的 `lang`，並納入會影響生成內容的設定一致性檢查。`jp` 與 `ja` 視為相同設定。
- 在既有 generation／evaluation／report 中繼資料或 sidecar 中記錄該階段的語言；具體位置須符合各階段 schema 及版本規則。
- 不為語言設定改變測試問答 JSONL 的必要欄位、不把敘述語言代碼加入所有資料列，也不改變 ID、狀態與判定契約。
- effective settings 與工作中繼資料分別記錄生成語言要求 `lang`、實際使用的介面／固定文字語言 `ui_lang`，範本建立另記錄實際資產語言 `template_lang`。後兩者由可用資源決定，不是額外 CLI 引數。例如 `--lang fr` 的 `lang=fr`、`ui_lang=en`；範本建立時另有 `template_lang=en`。這些值不代表模型輸出的實際語言或受測 Agent 回答語言已被偵測。

### Resume

- 既有支援 `--resume` 的階段，省略 `--lang` 時恢復工作階段中保存的值；需保留「未指定」與「明確指定 en」的差別。
- 明確指定相同語言可續跑；指定不同語言須在任何新工作或寫入前拒絕，說明原設定與本次設定。
- 若要改用其他語言，使用新工作與新輸出位置，不在舊工作階段混入另一語言的生成內容。
- 沒有語言欄位的舊工作階段維持原版本的續跑相容政策，不默默補成 `en`。若無法可靠恢復原先生成行為，應停止並說明使用相容版本續跑或建立新工作的方式。
- 本需求不擴大 `--resume` 的支援範圍；不支援續跑的模式仍依既有規則拒絕。

## 範本與文件

- 五種完整支援語言的 Skill 範本使用本機維護的對應資產，不以模型臨時翻譯；建立範本都不需要 API key 或 provider 呼叫。其他代碼使用英文資產並顯示簡短提示，不把英文範本標示成該代碼的翻譯版本。
- 各語言範本在工具、參數、方法、必須執行的步驟與範例能力上保持一致；程式碼範例仍可直接使用。
- 使用英文範本搭配 `--lang fr` 執行階段時，仍由當次執行的語言政策要求模型生成法文；範本文字語言不限制模型生成語言。
- 範本另建立 `language.json` 記錄生成要求、實際介面與範本資產語言。切換語言不會更改預設目錄、Skill 與指南檔名或 `--force` 保護；`--force` 只覆寫受管理的三個檔案，保留其他檔案，也不會在執行階段翻譯或覆寫使用者 Skill。
- 相關中英文 README 與網站 CLI 說明同步補上支援值、預設、完整流程範例、續跑與受測 Agent 邊界。
- 本 PRD 是語言行為的依據；實作時同步對齊 [CLI 輸出契約](PRD-cli-output.zh-TW.md) 與 [Skill 範本 PRD](PRD-skill-template-generation.zh-TW.md)，其他階段的生成、評估與報告契約仍有效。

## 實作方向

- 建立共用的語言正規化、固定文字查詢與模型語言指示介面，避免各階段自行判讀 `lang`。
- 固定文字採用可維護的五語資源。完整支援語言應有完整鍵值；缺漏翻譯須由檢查發現，不將語系鍵名直接顯示給使用者。其他語言代碼使用英文資源是明確定義的行為，不冒稱已有對應翻譯。
- 語言以明確參數或工作上下文傳遞到 parser、進度、互動、錯誤呈現、階段 API、模型、報告 renderer 與範本建立；避免程序全域可變語系影響同時執行的工作。
- 優先檢視現有 `cli.py`、`progress.py`、`interfaces.py`、`browser_target.py`、`skill_agent.py`、`skill_generation.py`、`situation.py`、`evaluation.py`、`reporting.py`、`skill_templates.py` 與 `work_session.py`，以實作時原始碼為準。
- 語言新增後，模型 token 預算應計入語言指示，沿用既有預算與重試機制。
