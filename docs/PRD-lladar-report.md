# LLaDAR Markdown 評估報告

## Status

已獲使用者確認並實作。此規格涵蓋 `lladar report <eval 輸出> --output <Markdown>`，可接受 schema v2/v3 的一般 `eval` JSON，以及 `eval --from` 目錄。

## 目的

將資料集、執行方式、待測對象、評分依據與測試結果整合成可供人閱讀的繁體中文報告，同時保留數字、來源與逐題回答的可追溯性。

## 行為

1. `run-agent` 在可用 Akasha 憑證時，透過只讀工具檢視工作副本中的 README、程式碼和設定，將有檔案證據的專案概述、專案／Agent／模型名稱、判定狀態及候選名稱寫入 `<answers>.run.json`。失敗不取消已取得的回答；記錄缺漏原因。不得把轉接器探索模型或評審模型當成待測模型。
2. `lladar report` 從評分檔、資料集 manifest／案例、封存評分方案、回答檔及執行紀錄擷取可用證據。檔案缺失或雜湊不符時，標示缺漏並產出仍可核對的部分；缺乏可核對的評分摘要或逐題狀態時失敗。
3. 程式計算題型分布、逐題狀態、分數與來源指標表格，並逐筆輸出題目、原始回答、狀態、分數和原因；不得把全量逐題資料送交撰寫 Agent 計算。
4. `akasha.agents` 只讀有界的封存證據與程式統計，撰寫測試資料介紹、測試方法、待測對象、評估方法及結果解讀。模型不能改寫統計數字；缺乏證據的身分或結論標示未記錄／無法確認；程式碼推斷的身分標示為推斷並附檔案來源。
5. 報告明列分母、覆蓋率、跳過／錯誤原因、不支援來源指標、評分規則衝突及與來源研究的可比性限制。零題成功評分仍可產報告，並聲明沒有可解讀的評分結果。
6. 報告寫入 `--output` 指定的 Markdown，另存 `<output>.meta.json`，記錄輸入雜湊、報告模型與生成時間。撰寫 Agent 失敗或產生不合契約內容時指令失敗，保留 `<output>.failed.json` 診斷；不留下部分完成的 Markdown。
7. 預設不覆寫現有報告或旁存檔；只有 `--force` 可覆寫。

## 驗收

- v2 JSON、v3 JSON、`eval --from` 目錄皆能以同一 CLI 產生報告。
- 大量案例的統計與逐題附錄由程式完成；Agent 輸入沒有完整回答列表。
- 有憑證的 `run-agent` 封存帶來源的專案概述；概述失敗不破壞回答檔。
- 缺失原始檔、零題成功評分、來源指標不支援、評分方案衝突、撰寫 Agent 失敗均有明確報告或診斷。
- 檢查報告統計和逐題資料與原 `eval` 產物一致，且未將評審模型誤標為待測模型。
