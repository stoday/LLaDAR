# PRD：由 Agent 自動探索、驗證與重用網站問答接入方式

## 1. 狀態、範圍與文件關係

- 日期：2026-10-13，Asia/Taipei。
- 版本：草稿 v0.5。
- 狀態：使用者已採納並要求開始實作；進度與證據見[實作驗證紀錄](browser-agent-discovery-validation.zh-TW.md)。本文件不代表四個目標已驗收完成。

## 2. 問題與現況依據

目前已有 HTTP／串流、文字 WebSocket 與 DOM 材料擷取，也已有以 Akasha 建立模型的抽取介面。問題是探索動作、候選方法及成功判斷仍受固定流程限制。

2026-10-13 改版前的本機工作樹檢視；下列舊模組已在實作階段移除，這張表保留問題依據：

| 現況 | 來源 | 造成的限制 |
| --- | --- | --- |
| 正式 CLI 主要等待使用者手動送出校準題 | [BrowserTarget.prepare](../src/lladar/browser_target.py) | 尚未由探索 Agent 完整接手正常使用流程 |
| 輸入探索已有模組及測試，但未接入正式 CLI 主流程 | `browser_operation.py`（已移除） | 測試模組成功不能宣稱 CLI 已能自動探索 |
| 操作候選只表達 frame、input、submit | 同上 | 無法表達選工作區、開新對話、導頁等多步驟 |
| adapter 計畫限定少數 CSS 欄位與 busy 條件 | `browser_adapter.py`（已移除） | Agent 主要填寫參數，缺乏組合不同接入方法的空間 |
| 通訊模板以單一請求替換問題為主 | [RequestTemplate](../src/lladar/browser_target.py) | 難以處理建立會話、輪替識別碼、送題與輪詢等流程 |
| HTTP／WebSocket 通訊完成主要依傳輸結束 | `playwright_driver.py`、`websocket_capture.py`（已移除） | 本題完成但連線仍開啟時，可能無法取得完成結果 |
| 已改由 Akasha 路由抽取模型，但目的地揭露仍偏概括 | [extraction_provider.py](../src/lladar/extraction_provider.py)、[providers/akasha.py](../src/lladar/providers/akasha.py) | 新版仍需揭露實際解析出的目的地，而非只顯示「Akasha 設定」 |

以上是現況證據，並非要求保留原模組切分。新版應整合既有能力，避免在同一功能旁新增一條未接入正式入口的平行實作。

### 2.1 既有通訊支援的精確範圍

| 類型 | 已有能力 | 新版需補足 |
| --- | --- | --- |
| HTTP／REST API | 錄製請求，替換問題重送，收取文字／JSON 回應 | 探索多請求依賴、動態 session／request ID、非同步 ack 與結果查詢 |
| SSE／HTTP 串流 | 擷取有序文字串流，目前主要依串流結束確認完成 | 支援連線保持開啟時經驗證的本題終止，不能只靠 EOF 或固定 event 名 |
| 原生文字 WebSocket | 錄製／重播文字訊息，目前要求正常關閉 | 探索持續連線的訊息關聯、本題完成及多輪訂閱／送題流程 |
| 二進位／Socket.IO／框架通訊 | 尚未完整支援；部分服務已有 DOM 收取後援，不等於通訊接入成功 | 由 Agent 依觀測調查封裝與協定、生成或組合適配方法，通過隔離試跑及獨立驗證後使用；不以預先存在的框架專用 adapter 為前提 |

上述為本機現況，不代表 ChatGPT、Gemini、EIP 或所有 Streamlit 版本的實際協定。四個驗收目標使用何種通訊、哪些呼叫相依，均須由當次錄製及試驗確認，不能事先把網站名稱映射成固定方案。

### 2.2 網路接入主體與 DOM 輔助角色

從瀏覽器啟動至登入完成、進入服務、輸入、提交與回答完成，持續建立本機必要觀測。已授權的網站錄製材料可原樣交給探索／抽取模型，包括 URL、headers（含 Cookie／Authorization）、請求與回應 body、客戶端 JavaScript 及二進位封包；不以私密值檢查阻擋或改寫這些材料。Agent 在授權後分析與問答相關的網路流程，包括前置呼叫、session 綁定、送題、訂閱／輪詢、材料收取與完成訊號。此範圍不開放讀取 `.env`、provider key 或 browser storage，DOM 密碼／OTP 欄仍受保護。

找到 endpoint 是候選證據，不等於方法已通過。Agent 須用新回合證明錄製的整個流程可以重複執行，不只複製一個 URL 或固定 payload。

- **主要接入候選**：HTTP／REST、SSE、WebSocket 及其可驗證組合。網路方法經驗證能可靠完成問答時，正式執行採用該方法；僅在經驗證需要的地方使用 DOM 輔助，不把 DOM 送題或收取定為每題必經步驟。
- **DOM 操作輔助**：登入後開啟服務、選擇工作區、建立探測回合及必要正常 UI 操作；允許 DOM 送題＋網路收取。
- **DOM 核對輔助**：提供當輪可見完整回答，檢查網路收取是否忠實，或提供獨立完成證據；DOM 核對不自動等同 DOM 收取。
- **DOM 收取後援**：網路方法尚未經證明或目前能力不足時，仍可驗證並使用 DOM 收取，但需保留網路探索紀錄與缺口。

以上是產品方向，不是「HTTP 失敗後固定試 SSE，再試 WebSocket，最後 DOM」的程式分支。Agent 依實際證據決定必要探索與方法組合；不因既有擷取器失敗就認定網站沒有可用 API，也不讓 DOM 成功掩蓋通訊能力缺口。

驗收須分列**送題方法、收取來源、完成證據與核對來源**。只以 `transport`／`dom` 一個標記，無法表達上述組合。

## 3. 產品目標與成功定義

| 要求 | 定義 | 必要證據 |
| --- | --- | --- |
| 有效 | 指定問題確實送進使用者選定的問答服務，並被接收處理 | 真實提交事件、本題識別及服務／畫面接受證據 |
| 可行 | 換問題、連續問答及正常會話變動後，方法仍可重複使用 | 未參與探索的新回合、策略重載、session／rerender 測試 |
| 正確 | 收到的是本題完整的網站回答，保留原文且排除無關材料 | 本題來源關聯、完成證據及獨立原文核對 |

「正確」指接入及忠實收取，不代表受測 Agent 答對題目。網站的拒答、不確定、錯誤觀點與不正確答案也須忠實保存，交由後續 `eval` 評估。

產品目標：

1. 使用者不必提供 API schema、Cookie、selector、JSON path 或網站框架名稱。
2. Akasha Agent 能提出、測試與修正多種候選接入方法，而非只接受宿主預選的唯一路徑。
3. 送題、收取、題目關聯與完成判斷可獨立組合；支援多步驟與動態會話資料。
4. 只有取得必要證據的方法能進入正式資料集執行；成功必須由宿主驗證。
5. 已驗證的方法可保存並重新檢查；正常網站變動可在額度內重新探索。
6. 使用者能看見正在探索什麼、候選失敗在哪裡，以及目前證明到哪個階段。
7. 未預先支援的協定或封裝，Agent 能在通用工具與執行機制內自行調查並產生適配程式；換網站或框架不預設需要人工新增核心功能。

本版不宣稱支援任意網站。遇到工具能力不足或證據不足，須回報具體缺口；不能以 Agent 自我評分或非空文字假裝已接通。

## 4. 舊契約的修訂與保留

| 項目 | 舊規格 | 新版要求 |
| --- | --- | --- |
| 校準提交 | 使用者必須手動送出一次校準題 | 保留人工校對錄製：登入及授權後由宿主顯示精確題目，使用者在真實頁面送出並等待完整回答；Agent 只能從該回合開始建立接口 |
| 路徑選擇 | transport 優先，能力不足才選 DOM | 網路接入是主要方向、DOM 作輔助；Agent 依錄製與驗證組合方法，不把固定協定順序當成接通規則 |
| 策略表達 | 單一請求模板或固定 CSS 表格 | 可組合多步驟、分支、受限等待及動態綁定，不限制為一個請求或一個答案節點 |
| 長連線 | 通訊路徑須關閉才完成 | 本題完成與連線生命週期分開；允許經驗證的應用層完成條件 |
| 執行失效 | 舊 PRD 要求固定路徑、失敗停止；現況已有有限的已觀察 DOM 修復 | 先停止新題派送；可在剩餘授權內探索修復並重新驗證，不能盲目重送已提交的題目 |
| 全文核對 | 固定人工 MATCH | 獨立忠實度核對持續必要；具可信自動原文基準時可自動核對，否則保留人工 MATCH 或標示未驗證 |
| 用量公式 | 固定最多 N+2 次抽取 | 分別揭露探索、探測、驗證、正式執行與修復額度，共用累計帳本 |
| 低額度 | 舊文件的 120 KiB、8192 tokens 等常數 | 沿用集中資源設定及所選模型 profile，可覆寫；不把舊數字重新寫入新流程 |
| 保存範圍 | 不保存網站 selector | 為重用允許保存必要操作策略於本機私有產物；一般摘要與公開報告不含 selector、私有內容及憑證；使用者要求的本機 Akasha verbose trace 另依第 12 節處理 |
| 模型目的地 | 曾有供應商專用抽取限制 | 所有模型角色均走 Akasha 與 `--model` 設定，不另建 provider 專用 HTTP client |
| 協定擴充 | v0.2 使用預先提供的受信任 codec，禁止 Agent 生成解碼程式 | Agent 可生成協定／會話適配程式；在通用隔離環境試跑，經宿主驗證才使用，不預先列舉框架支援清單 |
| 錄製材料 | 網路材料先遮蔽／投影，識別私密值時拒絕交給模型 | 已授權網站錄製原文可交給所設定模型，不再以 `protected_protocol_material` 或同類私密值檢查阻擋 |

持續保留：

- 使用者自行登入、完成 MFA／OTP／CAPTCHA；Agent 不讀取或操作 DOM 密碼／OTP 欄。網路錄製中的登入或 session 資料依已授權原文傳輸範圍處理。
- 網站請求與模型資料傳輸須有明確授權；人工登入不等於授權探測或外傳。
- 答案仍由模型直接閱讀本題材料並忠實抽取；不恢復生成 parser、答案解析 DSL、用來選取答案的 JSON path 快取或無模型捷徑。
- 探索與抽取不得讀取 `expected_answer`、評分結果或未來正式題目。
- 正式三欄資料及 id-keyed／trial sidecar 契約持續沿用，失敗不能補造 `actual_response`。
- 三欄仍為 `question`、`expected_answer`、`actual_response`；失敗回應維持 `null`，完成試次的原文不被修復流程改寫。
- 不修改目標網站程式碼，不要求目標新增 API，不變更 `--project`、`--service-url` 或 situation 語意。

## 5. 使用者流程

1. 使用者執行既有 `run-agent --page-url` 命令；LLaDAR 開啟自己的可見瀏覽器。
2. 終端提示使用者完成登入、開啟可對話的頁面／視窗並保持輸入框空白，準備好後再回到終端按 Enter。若有多個分頁／視窗，顯示編號與服務 origin，讓使用者選擇對話頁面；不得猜測最後開啟的分頁。交接時已有的頁面均不供探測操作或清理關閉使用。
3. 首次模型探索或自動探測前，CLI 揭露網站範圍、模型目的地、資料種類及各階段額度，取得一次完整授權。
4. 宿主顯示一個含唯一回合標記的精確校對問題。使用者在目前作用中的真實對話頁手動輸入並送出，等待完整最終回答後回到終端按 Enter；錄製從提示前開始，必須確認問題出現在該回合的網路事件或頁面中。
5. Agent 只能先檢視這個校對回合的 DOM 與網路事件，建立送題、回答關聯及完成證據；登入與頁面載入流量不混入初始事件清冊。
6. Agent 根據校對回合建立接口候選，再由宿主以新的自動探測回合驗證。失敗時只暴露該次失敗回合供修正，不能盲目重送。
7. 以未參與候選建立的新回合驗證有效、可行、正確；通過後保存策略版本與驗證證據。
8. 宿主以已驗證策略逐題執行正式排程，維持每題來源、完成及結果檢查。

候選方法的 `setup` 是可重複的準備階段。宿主每執行一批開頁、切頁、展開面板或等待動作後，必須重新觀察目前作用中的分頁，再次呼叫 `setup`；只有候選以新觀察明確回報 `complete=true`，且該次沒有尚待執行的動作時，才建立題目回合並把題目交給 `send`。交給候選程式的可操作 DOM frame 與連線僅能來自宿主選定的作用中分頁，其他分頁只保留於宿主的頁面清冊，不得混入控制項選擇。每個新候選 revision 以空白執行狀態開始，不能沿用前一版的分頁引用或「已準備」旗標。

人工校對回合完成前不啟動探索模型，也不能宣稱已知服務接口。使用者只示範正常問答，不提供 endpoint、selector 或協定判讀。校對完成後，Agent 才能根據該回合新產生的 HTTP、SSE、WebSocket、DOM 與完成證據建立**接口候選**。接口候選另以新的探測回合驗證，通過後才進入既有的 held-out verification 與正式資料集派送。
9. 失效時停止新題派送，保存進度，依本文件的修復及未知提交規則處理。
10. 結束時產生現有作業報告及探索證據報告，指出成功、部分完成或待補證據的範圍。

所有非正式回合，包括初始探測、獨立驗證、重用／resume 驗證及修復探測，都須遵守會話隔離規則。進入正式執行前確認既定正式會話狀態；不能把探測歷史混入正式題目，也不能默默清空、刪除或重建使用者的會話。無法維持要求的會話語意時，停止並明示缺口。

人工示範校對回合是每個新 `--page-url` 探索的固定輸入；服務選擇及 MATCH 仍依實際頁面與全文證據進行。使用者不必找 API、selector 或解釋協定。既有 TTY 與可見瀏覽器契約保持；本版不新增無人值守登入模式。

## 6. Agent 與宿主的責任

### 6.1 探索 Agent

探索 Agent 使用 Akasha 的工具介面，負責：

- 解讀可見頁面意圖、必要結構與本次互動的網路證據。
- 提出可執行候選、說明其需要驗證的假設及使用的觀測引用。
- 根據實際工具結果修改操作、來源關聯、材料收取與完成條件。
- 在多個已通過驗證的方法間，依成功紀錄、延遲、呼叫成本及可維護性選擇。
- 發現協定或封裝缺口時，讀取已授權觀測、客戶端資源及規格，生成／組合候選適配程式並用工具試驗；不能只因現成 adapter 不存在就直接停止。
- 確實缺少宿主基礎能力、必要資料或可驗證證據時，提交具體缺口，而非硬選現有路徑或修改核心程式。

不以固定網站名、框架名、class、欄位名、event 名或 Agent 說「完成」作為成功依據。

### 6.2 宿主程式

Python／瀏覽器宿主負責：

- 執行通用工具、維持瀏覽器 session、權限範圍及正確的瀏覽器 owner thread。
- 在提交前建立本題識別與觀察基準，記錄提交、接收、完成及抽取的狀態。
- 驗證工具參數、證據引用、實際操作、額度與 checkpoint。
- 保持原文、時間順序及來源資訊；執行候選試跑與獨立驗證。
- 保存合格策略與正式輸出；阻止無證據的成功與重複派送。

固定的是這些驗證責任與工具契約；網站接入的實際步驟由 Agent 根據觀測建立。

### 6.3 答案抽取與評估

- 抽取模型只接收已完成、與本題綁定、已授權的材料，輸出既有最終回答。
- 探索策略只能描述操作、材料範圍、識別與完成條件，不能夾帶代答、摘要、翻譯、修正答案或答案內容解析程式。
- 本題材料可有多個區塊；抽取須保留完整正文、原有語言、數字、否定、段落及格式。
- `eval` 才接收預期答案並評分；接入探索、抽取與忠實度驗證彼此不能利用評分基準修補結果。

## 7. 通用工具與策略需求

以下是能力契約，不是已實作的工具名稱或固定 schema。實作可整合既有工具，但必須覆蓋這些能力，不能把新流程再次壓回固定六欄表格。

| 能力 | 必要行為 |
| --- | --- |
| 觀察頁面 | 提供必要可見文字、可存取性／DOM 結構、控制項狀態與可定位引用；處理 rerender 後的新觀測 |
| 正常 UI 操作 | 開啟面板、在授權範圍導頁或切換頁面／frame、選對話入口、輸入及提交；可組合成多步驟 |
| 觀察通訊 | 關聯 HTTP、串流及可觀察的 WebSocket 訊息，保留順序、時序、請求及回合識別 |
| 檢視候選材料 | 依引用讀取與本次接入相關的封裝、回應區塊及狀態事件；分頁不可破壞完整性 |
| 調查協定 | 檢視已授權 frame／封包的原文、結構與時序；讀取網站正常載入的客戶端資源、公開規格及 schema |
| 建立候選 | 提交操作、收取、關聯與完成條件，以及必要 session／request ID 動態綁定 |
| 生成適配程式 | 在隔離工作區提交 codec／協定／會話程式及依賴描述；以固定宿主工具編譯、試跑及回報錯誤 |
| 試跑及驗證 | 執行受限真實回合，回傳宿主測得的結果與精確失敗分類 |
| 保存及修復 | 版本化提交策略、查詢本題狀態、修正失效部分並重新驗證 |

策略至少需分開表達：

1. **送題流程**：前置操作、提交方式、會話規則及正常變數更新。
2. **材料收取**：來源、區塊範圍、排序、追加／替換等傳輸或畫面行為。
3. **本題關聯**：宿主回合識別與可觀察 request/message/conversation 證據的關係。
4. **完成條件**：本題終止證據、必要交叉檢查及未完成處置。

必須能表達：

- DOM 送題＋HTTP／串流／WebSocket 收取。
- HTTP 送題＋DOM 收取。
- 建立對話 → 取得動態 ID → 送題 → 輪詢／訂閱 → 收取完整材料。
- 純 DOM、多區塊正文及正常重新渲染。
- 由可驗證條件驅動的分支及受額度限制的等待／輪詢。

### 7.1 Agent 自行調查及產生協定適配

協定適配是探索 Agent 的交付內容，不是要求開發者逐站新增的前置功能。Streamlit 是驗收樣本，不是核心程式內的一個固定分支。

探索循環如下：

1. **確認缺口**：以觀測證明現有方法不能處理哪一層，例如二進位封裝、握手、動態訊息識別或長連線完成；不是看到網站名稱就選 codec。
2. **調查依據**：檢視實際問答的材料結構、時序、網站正常載入的客戶端程式、公開協定文件、schema 或可取得的套件資訊。網站的伺服器私有程式、fixture 後端及答案 oracle 不提供給 Agent。
3. **產生候選**：Agent 可自行編寫適配程式、依據取得的 schema 產生 codec，或要求宿主配置可用依賴；不限於從預先寫好的 adapter 清單挑選。
4. **本機試驗**：在隔離工作區測試材料解碼、完整順序、session／訊息識別、控制事件與受限編碼。宿主提供固定工具及結構化錯誤，Agent 依證據修正。
5. **新回合驗證**：通過本機試驗後才使用受控瀏覽器／通訊工具試跑新回合，沿用來源、完成、全文核對、提交與額度契約。
6. **保存與修復**：合格程式連同 revision、依賴版本、內容雜湊及證據保存；新 session 或協定變化時由 Agent 再調查、修正、重驗證。

沒有現成 codec 不足以直接判定不支援；缺少可取得的必要 schema、材料、授權或執行能力時，仍須如實回報，不能保證只靠若干封包就還原任意未知協定。這是證據不足的結果，不能改成預先排除所有二進位網站。

既有通用 codec／套件可重用，但不是硬性先決條件。宿主提供的是通用觀測、工作區、依賴管理、隔離執行及驗證能力；新增網站所需的具體協定／會話方法由 Agent 產生，不要求改 LLaDAR 核心才能使用。

### 7.2 生成程式的範圍與執行契約

生成的適配程式可處理傳輸封裝、握手、編碼／解碼、session／訊息 ID、順序與控制事件，並輸出帶來源及順序的完整材料。它不能選取、摘要、修正或生成最終回答；答案仍交給無工具的直接抽取模型。因此本版允許**協定適配程式生成**，仍不恢復**答案 parser 生成**。

- 程式只能經固定宿主工具提交及執行，不在主程序以不受限 `exec` 或 shell 執行。
- 候選在可執行限制的隔離環境中運行，限制檔案、網路、子程序、記憶體、時間與輸出；工作區外讀取、環境設定、provider key 及 browser storage 不可取得。宿主提供的已授權網站錄製原文可用於協定適配。
- 與網站互動經宿主的授權通訊／瀏覽器工具；正常握手、建立會話與送題可按契約由宿主代理。生成程式不能自行建立未計數請求、重新登入、重送未知回合或未經授權改動網站狀態。
- 已授權錄製中的憑證、session 值及未知二進位不強制轉成引用或去敏投影；原始材料與解碼輸出可提供給模型。Base64 只是二進位的傳輸表示，不代表去敏。
- 候選的 stdout、stderr、結構化錯誤與解碼輸出仍受來源、傳輸範圍及資源限制；取消以已知私密值及其編碼表示拒絕交給模型的檢查。一般進度摘要與公開報告不印材料原文；使用者啟用的本機 Akasha verbose trace 可顯示 Agent 實際收到的工具參數及回傳。
- Agent 可提交依賴需求，由宿主在 adapter 專用隔離環境按既定來源與資源政策配置並鎖定版本，不直接執行任意安裝指令，不修改 LLaDAR 或全域環境；版本及內容雜湊納入重用與 resume 相容性。
- 工具提供可用的通用資料／控制操作及必要條件分支，不把適配程式再限制為固定框架 schema。宿主驗證來源與能力使用，不以白名單列出全部網站協定。
- 本機試跑成功只代表已通過該層測試；正式使用仍須新回合獨立驗證。功能測試通過不解除執行限制，也不授權讀取工具範圍外的檔案、環境設定或 provider key。
- 正常工具可操作網頁，但不得修改 DOM 偽造回答或依賴寫入 framework 私有狀態。Canvas／OCR、自動 CAPTCHA 與任意主程序程式執行仍不屬首版範圍。

隔離環境缺少必要且可強制執行的限制時，候選保持待驗證並回報宿主能力缺口；不能以提示詞、Agent 自律或單純開 subprocess 代替執行隔離。DOM 後援仍可另列，但不能代替協定探索驗收。

## 8. 本題關聯、完成與原文忠實度

### 8.1 本題關聯

- 每次提交前建立唯一 `turn_id`，保存必要的提交前材料基準。
- HTTP 狀態碼成功、問句出現或答案非空不能單獨證明本題接收與回應關聯。
- 必須區分舊答案、其他對話、背景 push、狀態訊息、ack 及本題材料。
- 相同問句或相同答案仍是不同回合；不能以文字 hash 作為唯一回合識別。
- 動態 session／nonce／request ID 須依當次觀測建立有效綁定；已錄製原值可供 Agent 調查，但不能將過期值當作可重複使用的會話證據。
- 可使用受信任的 metadata 結構／路徑引用處理 session、request ID 及控制事件；這不授權生成選取或改寫答案內容的 parser／DSL。

### 8.2 完成條件

- 「本題已完成」與「HTTP／WebSocket 連線已結束」分開建模。
- 候選可依已觀察的應用事件、特定回合狀態轉移或可驗證 UI 行為提出完成條件。
- 任意 `done` 字樣、固定 event 名、固定 sleep、文字暫時穩定或無新網路流量都不足以單獨通過。
- 宿主檢查條件是否屬於本題、是否為正常終止、是否與獨立原文證據一致；新回合須重現必要行為。
- 完成條件必須有反例測試：背景完成事件、先出現 ack、段落間長停頓及故意缺尾段不能被當成完整回答。
- 不完整、歧義、無正常終止或全文不可得時，不呼叫模型猜測完成，不發布部分 `actual_response`。

### 8.3 忠實度核對

- 核對的是**同一回合**網站的完整原文，不要求不同問題或不同回合返回相同答案。
- 本機測試以宿主持有且不提供給探索／抽取模型的完整原文 oracle 核對。
- 真網站可使用獨立完整畫面來源與通訊來源交叉核對；共享同一擷取器或同一模型的兩份結果不算獨立基準。
- 自動基準的資格由宿主以可檢查證據建立，不能直接沿用候選的答案範圍、完成條件或 Agent 自稱完整。不同來源若共同漏掉尾段，即使文字一致也不能通過。
- 若兩來源表示法不同，差異規則須預先定義並保留原文；不能用語意相似度掩蓋缺字、漏段、數字或否定變化。
- 只有具可檢查、完整且獨立的自動基準才能替代人工 MATCH。否則使用者核對全文，或結果保持未驗證。
- 結構正確、來源正確、完成正確及原文忠實度須分別記錄；一項通過不能代替其他項。

## 9. 驗證、正式執行與修復

### 9.1 狀態與允許動作

| 狀態 | 意義與下一步 |
| --- | --- |
| `awaiting_login` | 等待使用者登入；尚未開始自動送題 |
| `awaiting_consent` | 等待本版探索與資料傳輸授權 |
| `discovering` | 觀察及提出候選，未取得接通證明 |
| `candidate` | 候選已保存，等待實際試跑 |
| `probing` | 在額度內執行探測回合並收集證據 |
| `verifying` | 用新回合及獨立基準檢查必要性質 |
| `verified` | 指定策略版本及範圍通過；允許正式派送 |
| `running` | 逐題執行已驗證策略 |
| `repairing` | 停止新題派送，觀察或修正策略；不能直接回到 `running` |
| `needs_input` | 等待登入、服務選擇、全文核對或範圍授權等具體補充 |
| `blocked` | 無法符合必要條件；保存已完成成果及首次原因 |
| `completed` | 所有排程試次及產物發布完成 |

`test_operation` 之類工具只檢查控制項時，只能記錄操作綁定通過，不能直接標示完整接入 `verified`。

### 9.2 候選驗證

- 探測題獨立於正式資料集及其預期答案，須符合使用者指定的服務測試範圍。
- 候選先通過自己的新 probe，再以一個未用於候選建立的獨立驗證回合確認；人工校對、probe 與該次驗證合計提供三個完整回答回合，亦可共同資格化 DOM 參考來源。
- 驗證題應能暴露不同長度、格式、延遲及相同內容的關聯問題；真網站只能量測實際可產生的行為，不宣稱未測過的性質。
- 多候選可共用已授權的同回合觀測；改變操作方式需新回合時，必須使用剩餘探測額度。
- 第一次成功只代表本次 round-trip 通過；策略需完成新回合驗證才能發布為可重用。

### 9.3 提交狀態與重送

宿主必須區分 `not_attempted`、`attempted_unknown`、`accepted`、`completed`，並保存狀態演進。提交可能已被網站接受時，觀察與修復不得重置該狀態。

- 真正 click／Enter／網路提交之前，先原子保存本題識別、策略 revision、預算保留／扣除及 `attempted_unknown`；持久化失敗則不得提交。
- 取得新證據後才轉為 `accepted`／`completed`。送題前狀態已保存、但執行結果未保存就崩潰時，續作仍視為未知，不能還原成 `not_attempted`。
- 只有宿主能證明提交未發生時才撤銷保留額度或回到未嘗試狀態；Agent 的推測不能作為依據。

- `not_attempted`：修復後可按原授權執行一次提交。
- `attempted_unknown`：先查詢／觀察原回合；未能證明未送出時不盲目重送。
- `accepted`：收取或修復收取方式，不再提交同題。
- `completed`：保存結果；若抽取失敗，保留回合狀態，不以重送取得另一份網站答案。
- 只有網站具已驗證的冪等機制且使用同一有效鍵時，才可將受控重送列入策略；重送的實際請求仍計入帳本。

### 9.4 修復與恢復執行

- 每個正式回合仍執行來源與完成檢查。失效立即停止新題派送，不繼續以舊策略產出可疑結果。
- 在已授權且剩餘額度內，Agent 可改進定位、session 綁定、來源或完成條件；保存新的策略 revision。
- 新 revision 必須通過獨立驗證，確認與排程會話語意相容後，才能恢復尚未送出的試次。
- 修復及所有非正式探測不得污染正式對話。策略須能隔離探測會話，或證明回到原正式會話；無法做到時停止並回報，不默默新建正式 session。
- 重新登入、帳號／工作區變更及導頁超出原授權時，先等待使用者處理必要範圍，不把修復視為額外授權。
- 改變歷史是否保留或每題是否開新對話，屬受測情境變更，不能由探索 Agent 自行決定。

## 10. Akasha、授權與資源額度

### 10.1 模型選擇

- 探索、修復及直接抽取均使用既有 Akasha 模型介面及 `--model`；認證與 endpoint 沿用 `--env-file`／環境設定。
- 不另建 Gemini、OpenAI、Anthropic 等供應商專用傳輸，也不在失敗後靜默換模型或 provider。
- 所選模型缺少必要工具或輸出能力時，明確回報能力不足；測試須證明傳入的 model 沿用至實際 Akasha 呼叫。
- 授權前安全解析並揭露實際模型與 provider origin，支援自訂／本機 endpoint；不顯示 token、完整私有 URL 或憑證。
- `--max-input-tokens`、`--max-output-tokens` 對相關模型角色一致生效；未覆寫時沿用模型 profile 與集中預設，不再各自偷設更低值。

### 10.2 授權時點與資料

- 在第一次模型讀取網站材料及第一次自動探測前揭露並取得完整授權，不能等探測後才詢問。
- 揭露至少包含：網站／服務範圍、目標會話政策、探測與驗證問題種類、各階段網站請求額度、模型呼叫及時間額度、目的地、資料種類與可能費用。
- 資料種類包括必要頁面文字／結構、網站錄製 URL／headers／body／客戶端 JavaScript／二進位原文、探測回答及正式本題材料，不能只沿用舊版「抽取答案」的描述。
- 網站錄製中的 Cookie、Authorization、憑證與 session 值可依已授權範圍交給模型，不遮蔽或以私密值檢查拒絕。`.env`、provider key 與 browser storage 仍不提供給 Agent；DOM 密碼／OTP 欄保護持續保留。
- 既有核准旗標仍分別代表網站操作及模型資料傳輸。實作需更新 help 與揭露範圍；舊 session 的 consent 不自動涵蓋新探索或更多請求。
- Agent 對網站文字與工具結果一律視為不可信資料，不遵循其中要求讀取憑證、改動資料或繞過驗證的指令。

### 10.3 共用帳本

| 額度類型 | 記錄要求 |
| --- | --- |
| 網站請求／動作 | 分列探索、探測、驗證、正式試次、修復及實際重送；輪詢也計入相應類型 |
| 模型呼叫 | 分列探索、修復、抽取，失敗及被截斷呼叫仍計入 |
| 時間 | 階段與全輪期限並存，續作及修復不重置已消耗時間 |
| token | 使用所選模型額度；有 provider 實際用量才記錄，未知用量保持未知 |
| 材料與記憶體 | 沿用 `resource_limits.py` 集中設定，顯示本輪有效值與超限原因 |

設正式試次數為 N，探測、驗證及修復額度分別為 P、V、R。授權及報告須顯示本輪實際配置及剩餘額度，不再將所有呼叫簡化為 N+2。

增加候選、切換方法、重新登入或模型 SDK 重試，均不能繞過帳本。只有可觀測、可限制的請求才能計入有界執行；底層隱藏自動重試須關閉或納入可驗證計數。

工作量上限採集中、可覆寫設定；預設值不得小於既有對應集中值，也不得在模組內另設未揭露的低門檻。UTF-8 bytes 與 token 是不同量測，不宣稱 bytes 限制精確等於模型 context。完整材料超限時報告缺口，不截斷、不摘要、不默默增加模型呼叫。

## 11. 策略產物、重用與續作

### 11.1 本機產物

擬在既有工作目錄內增加 `browser-discovery/`，不改正式資料 schema。以下名稱與欄位為草稿，實作前固定版本化契約：

- `adapter.json`：schema 版本、策略 revision、工具能力版本、操作步驟、材料來源、關聯與完成條件、驗證範圍及局部指紋。
- 必要的生成適配程式、schema 及依賴清單：與 adapter revision 綁定，保存來源依據、內容雜湊、依賴版本及資格驗證結果，作為本機私有重用產物，不加入公開報告。
- `discovery.jsonl`：候選 ID、觀測引用、嘗試分類、失敗原因、提交狀態、用量及驗證結果。
- `discovery-report.md`：可閱讀的接入依據、採用方法、已驗證／未驗證範圍、限制與產物位置。

保存必要 locator／endpoint 及協定操作的 adapter 是私有重用產物，不自動加入 Git、發布或附加到一般報告；生成程式可能含已授權觀測的網站資料。完整回答、prompt、頁面快照與原始封包不預設持久化；正常日誌與公開報告不印錄製原文。

### 11.2 重用資格

- adapter 綁定必要服務／頁面形狀、會話政策及工具契約，不依帳號密碼或原 session token 建立可攜身分。
- 首版採同一使用者本機、同一服務範圍的重用；跨帳號／服務分享與中央 adapter 市集另行規劃。
- 重載後檢查頁面與能力相容性，並在本輪額度內執行新驗證回合；載入舊 `verified` 標記不能直接跑資料集。
- 指紋改變是重新檢查的訊號，不等於必然失效；依實際能力與驗證結果決定。
- 生成的協定程式、schema、依賴或必要能力版本變更時，Agent 可建立新 revision；新版本資格與新回合驗證通過前，不沿用原有成功標記執行。

### 11.3 續作

- 沿用既有 work session、`--resume`、原子保存及正式發布規則，不創建另一套互不相通的恢復系統。
- checkpoint 包含策略 revision、工具版本、有效資源設定、授權範圍、累計用量及回合／試次狀態。
- model、資料集、會話政策或契約不相容的變更依既有 resume 規則拒絕；不能用重新探索清空已消耗用量。
- 已完成試次不重跑；`attempted_unknown` 的試次續作前須處理其狀態。
- 原始材料未持久化且無法重新取得時，明確記錄不可恢復的抽取缺口，不為了取得材料重送網站題目。

## 12. 進度、診斷與報告

- 正常進度顯示目前階段、候選方法概述、驗證項目、耗時及剩餘額度；等待時持續顯示心跳，不臆測百分比或 ETA。
- 終端不得只顯示 `read_event` 等內部工具名稱。每次模型分析與工具呼叫均顯示可讀目的、重要結果、目前工作及下一個資格門檻；例如「檢查校對回合的網路事件以尋找完成證據」、「接口候選完成，接著送新探測回合」。
- `--verbose` 預設轉送 Akasha 自己的公開 verbose trace，逐行標示 `[AKASHA]`；它包含模型回合、工具呼叫參數與工具回傳內容，讓使用者看見 Agent 實際查了什麼及取得什麼證據。它不宣稱提供模型未公開的內部 chain-of-thought。因 trace 可能包含已授權的 Cookie、Authorization、錄製正文、客戶端原始碼及候選程式，本機終端與 `--log` 產物均視為私有；`--no-verbose` 關閉該明細。JSONL stdout 維持清潔。
- 證據階段至少區分：登入完成、操作綁定、實際送題、回答來源關聯、完成確認、忠實度核對、新回合驗證、正式試次完成。
- 使用者看到「已接通」時，必須已達 `verified`；只找到 input 或取得非空回應不能使用該文字。
- 回饋需指明可修復的失敗，如來源歧義、ack 非答案、缺少完成訊號、動態 ID 失效或工具缺能力，不只回傳泛用 exception。
- CLI、`--log`、trial／run sidecar 與作業報告使用一致的宿主固定分類，不輸出原始 exception、完整 URL、selector、headers 或私有材料。
- 探索報告呈現「採用方法及依據」「候選失敗原因」「三項要求各自的證據」「未測範圍」，不保存模型私密推理。
- 操作文字與報告沿用共用 `--lang`；來源文字、目標回答、ID、schema key 及狀態碼不翻譯。
- 保持 JSONL stdout 清潔，進度與報告位置沿用既有 CLI 輸出安排。

### 13.4 必要驗收目標

以下四個目標由使用者指定，均為新版必要驗收，不能只選其中一個成功案例宣稱全部完成。網址用於指定驗收服務，不是核心程式的選路判斷條件。

| 目標 | 驗收入口 | 必測重點 | 獨立忠實度依據 |
| --- | --- | --- | --- |
| ChatGPT | `https://chatgpt.com/` 的實際問答頁 | 使用者登入後 Agent 探索實際問答網路流程、動態會話與本題完成，連續新回合及重載後驗證 | 同一回合網站完整可見答案；具資格的獨立自動基準或人工全文 MATCH |
| Gemini | `https://gemini.google.com/` 的實際問答頁 | 探索當次觀測的請求／事件相依，不假設網站使用開發者 API 或固定 SSE／WebSocket 形式 | 同一回合網站完整可見答案，按相同資格及核對規則驗證 |
| EIP | 使用者既有 EIP 問答服務頁；由本機私有 `--page-url` 設定指定 | 登入／2FA 後辨識正確服務與工作區、實際送題、非同步回應與完整原文；完成指定資料集全部試次 | 當輪 EIP 完整畫面答案；私有內容不進公開報告 |
| Streamlit 示範頁 | [原生示範程式](../example_project/streamlit_qa/app.py)，loopback URL 使用測試啟動的實際 port | 原生 `st.chat_input`／`st.chat_message` 及框架通訊；持續／二進位 WebSocket 的能力辨識與驗證，不改網站暴露額外 API | 測試宿主保存的獨立完整原文 oracle；另以原生 UI 全文核對 |

Streamlit 入口啟動方式沿用[示範說明](../example_project/streamlit_qa/README.zh-TW.md)。既有示範回覆 `Answer: 問句`，不呼叫外部模型；驗收時 Agent 可使用瀏覽器、協定調查及隔離適配工具，不得讀取示範後端原始碼／`agent.py` 或獨立 oracle。正常載入的前端資源、公開框架協定規格與 schema 可以作調查依據。需要長文、延遲、多段及 rerender 變體時，由測試宿主建立同框架示範變體，不能用新增 REST API 把原生協定問題避開。

Streamlit 必須另做「沒有預裝該框架專用 adapter」的驗收：Agent 根據當次可取得的協定及前端證據自行生成／組合適配方法，通過原文與新回合驗證。只讓 Agent 選擇我們手寫的 Streamlit decoder，不足以證明 BD-35；通過後保存、重用其產物則屬正常能力。

歷史驗證記錄已觀察到原生 Streamlit 使用持續、二進位 WebSocket，現有 transport-only 未通過而 DOM 路徑可用，詳見[歷史紀錄](streamlit-browser-validation.zh-TW.md)。新版須重新記錄當次框架版本與實際通訊；不能將舊 DOM 成功或單一版本結果當成新網路接入驗收。

### 13.5 四目標的共通驗收流程

每個目標須經公開 `run-agent --page-url`，使用真 Akasha 探索 Agent 與真瀏覽器完成：

1. 記錄驗收日期、頁面／框架版本（可取得時）、網站介面所選模型／模式（適用時）、控制 Agent 模型及會話政策。網站模型與 LLaDAR 的 `--model` 是不同角色，不能混稱。
2. 使用者完成必要登入與人工驗證；登入成功不算已接通。宿主顯示精確校對題，使用者在真實頁面送出並等待完整回答，不提供 endpoint、selector 或協定說明。
3. Agent 從該校對回合錄製探索實際網路流程；初始事件清冊排除登入／頁面載入流量，保存候選方法與驗證／淘汰依據，不預先指定該站應使用何種協定。
4. 建立候選並通過自己的新 probe 後，再完成一個未參與候選建立的獨立驗證回合。每輪取得完整回答，按同回合獨立基準核對，不要求各次回答相同。
5. 執行預先宣告的小型驗收資料集，至少五個正式試次；之後若另指定完整資料集，必須全部排程試次完成才記錄「該資料集完成」。探測／驗證不混入正式會話與計數。
6. 驗收資料涵蓋中文、Unicode／標點、否定／數字及有結構文字；長文與延遲行為只記錄網站實際產生及驗證過的範圍，不能把 prompt 要求視為網站已呈現。
7. 保存 adapter，以新執行載入並完成重驗證。布局、會話或能力不同時依本 PRD 重探索，不以直接重播過期 payload 掩蓋失效。
8. 提供 responses、trials、run sidecar、探索報告、策略版本、回合關聯、完成條件、核對方式與請求／模型用量對帳。錄製原文依本版授權範圍提供給模型，私有內容不附入公開日誌或報告。

驗收對象是**實際網站問答介面**。ChatGPT／Gemini 官方模型 API、EIP 替身、獨立 Python callback 或以其他框架仿造的 Streamlit UI，都不能替代以上指定目標。

網站要求登入、人工驗證、帳號用量不足或暫時不可用時，記錄 `needs_input`／尚未完成及當次缺口；不繞過限制，也不能把 skipped 當成 pass。這些操作條件於真正執行驗收時處理，本次 PRD 修改不啟動四個網站或發送題目。

### 13.6 接入結果分級與發布判斷

| 結果 | 判定 | 能宣稱的成果 |
| --- | --- | --- |
| 網路接入通過 | 透過已探索並驗證的 HTTP／REST、SSE、WebSocket 或組合收取本題完整材料；DOM 可供操作、完成輔助及核對 | 該目標在明列條件下已通過網路接入；另列送題是否仍需 DOM |
| 純網路執行通過 | 送題、收取及完成判定均走已驗證網路流程，正式回合不依賴 DOM 操作／收取／完成檢查；DOM 可在探索及獨立驗證時使用 | 該目標具備已驗證的純網路執行方法 |
| DOM 後援可用 | 本題答案的必要收取依賴 DOM；原文與可重複性已驗證 | 該目標可用 DOM 後援，仍列網路方法的未完成能力 |
| 未接通／待補證據 | 未取得關聯、完成、忠實度或重複性所需證據 | 尚未通過，明列缺口；不能標示網站支援完成 |

四個目標的新版完整驗收，均須通過網路接入、新回合、指定正式試次與重用驗證；純網路執行另列為能力成果，不強迫任何網站跳過必要正常 UI。只通過 DOM 後援可以發布為部分能力，但不能完成本次四目標的網路接入目標。

## 14. 實作切片與發布門檻

### 切片一：可用的探索循環

- 接入正式 CLI：通用頁面／通訊觀察、候選提交、受控探測、新回合驗證與證據報告。
- 首批涵蓋 BD-02～BD-05：JSON、ack＋DOM、純 DOM 多段、持續 SSE；不能只做未接線的模組或 harness。
- 先通過獨立 oracle 與必要負向案例，再以真 Akasha Agent 探索隨機 fixture。
- 此切片完成可標示上述明列能力，不能宣稱完整長連線、多步驟 session 或 EIP 驗收完成。

### 切片二：多步驟與長連線

- 擴充持續 WebSocket、動態 session、建立對話與輪詢，使用同一策略及帳本介面；提供 Agent 調查、生成、隔離試跑與資格驗證的通用機制。
- 以原生 Streamlit 及未預裝協定服務驗證自行適配；完成 BD-06～BD-10、BD-35～BD-39 及相應來源、完成反例，不預先手寫各站專用支援或新增目標 API。

### 切片三：重用、修復與恢復

- 完成策略版本、同服務重載、失效修復、正式會話隔離及 resume。
- 完成 BD-18、BD-20～BD-27，不以重啟 reset 掩蓋未知提交或用量。

### 切片四：真網站與完整驗收

- 經實際網站／資料傳輸授權完成 BD-29～BD-34 及第 13.4～13.6 節，逐一驗收 ChatGPT、Gemini、EIP 與原生 Streamlit 示範頁。
- 四目標均分列登入、探索、網路接入／DOM 後援、新回合驗證、正式 dataset 與 adapter 重用成果，不把 domain、class、固定 endpoint 或協定特例寫進核心。
- 完整新版發布需通過相應 BD-01～BD-39、四目標必要驗收、既有回歸、CLI／README／語系同步及版本化產物檢查；未通過目標明列為未完成。

證據層級必須分別標示：

1. 工具替身／單元資料流。
2. 真瀏覽器＋本機服務＋合成 provider。
3. 真 Akasha Agent／模型＋隨機本機服務。
4. 真網站已驗證回合。
5. 真網站指定完整資料集。

前一層成功不能代替後一層。每次報告實際題數、試次數、已驗證範圍及仍未完成項目。

## 15. 實作前需固定的細節

以下是待落實的介面細節，不改變本 PRD 的產品要求，也不是撰寫 PRD 前的阻擋：

- 可組合策略、生成協定程式的版本化表示法、資格驗證及工具錯誤回傳格式。
