# EIP 兩個 Agent 原型真站驗證（2026-10-14）

本次驗證使用可見瀏覽器，由使用者登入 EIP 並完成一次示範問答。錄製程序確認完整示範問題存在於實際 HTTP 提交請求，保存必要狀態後關閉瀏覽器。後續 Agent 和 adapter 測試沒有使用瀏覽器程序。

原型 `scripts/prototype_browser_agent.py` 依序執行材料 Agent 與 adapter Agent。材料 Agent 使用索引搜尋、請求追蹤和分頁讀取工具選出 37 筆事件。adapter Agent 取得所選材料、前一版程式及結構化真站錯誤，提交完整 `adapt(payload)` 程式並呼叫 `test_live`。失敗後保留已選材料與候選程式，下一輪再修復；通過後立即停止。

| 回合 | 真站結果 |
| --- | --- |
| 第一版 | 真 EIP 已收到新題並回傳資料；adapter 把 `http_stopped` 當成回答與完成證據，遭 `adapter_evidence_invalid` 拒絕。診斷指出錯誤事件種類及應查看的 response body／chunk／receive 事件。 |
| 第二版 | Agent 自行修正並重新提交；真 EIP 新題取得 135 字回答，來源與完成證據通過，`akasha.ask` 判斷回答合理。與示範答案並非逐字相同，且沒有逐字相同的通過要求。 |

本次共 23 次模型呼叫（含一次回答合理性判讀）、19 次網站 HTTP 請求（含收取回答的輪詢），產生並封存兩版候選程式。8 項原型契約測試及 Python 編譯檢查通過。私有錄製、登入狀態、完整回答與候選程式保存在 `.tmp/eip-live-loop-0e1e4324cd0c3e63-retry/`，不納入此文件。

**驗證範圍：** 這是重用示範對話、以新問題識別碼送題的原型驗證。它證明兩個 Agent 能根據真實錄製產生並修正送題／收回答的程式，且在瀏覽器關閉後成功執行一次真站問答。它尚未證明能建立與示範分離的新對話、執行完整資料集，或證明正式 `lladar run-agent --page-url` 已接通 EIP；主流程仍要求獨立新對話與不同的驗證門檻。
