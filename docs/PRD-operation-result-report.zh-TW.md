# CLI 作業結果報告

## 目的與範圍

每次 CLI 階段命令結束時，自動產生 UTF-8 Markdown 作業結果報告，讓使用者知道本次執行狀態、產出位置、問題及下一步。涵蓋 `create test-dataset`、`create situation`、`run-agent`、`eval`、`report` 與五種 `create *-skill` 命令；包含 situation 模式。階段指一次 CLI 命令，不是內部每一次模型呼叫。

Python API、help、版本查詢與無法辨識階段的命令不產生此報告。

## 行為

- 成功、完成但有作業問題、失敗、取消、需要人工確認，都嘗試產生報告。
- 保留原本退出碼、例外傳遞、模型呼叫次數及續跑規則。
- 報告由程式直接產生，沿用 `--lang` 的介面語言；其他合法語言代碼以英文呈現固定文字。
- 位置預設為主產物旁的 `OUTPUT.operation.md`；Skill 範本為目錄旁的 `DIRECTORY.operation.md`，不放入範本目錄。
- 已有同名報告時依序使用 `.operation-2.md`、`.operation-3.md`；即使 `--force` 也不覆寫歷次報告。
- 尚未解析出輸出位置或該位置無法寫入時，退回原工作目錄的 `.lladar/operation-reports/STAGE.operation.md`。
- 兩處都無法寫入時，只顯示警告並保留原命令結果。強制終止程序、斷電及無寫入權限時無法保證檔案存在。
- `--no-verbose` 仍顯示報告位置；正常執行時的報告位置會一起記錄到 `--log`。

## 報告內容

1. 階段、狀態、退出碼、開始與結束時間、耗時、要求與介面語言。
2. 允許記錄的設定與輸入檔案路徑；不複製輸入內容。
3. 記錄數及作業錯誤計數等已知統計。評估答案不正確不等於 CLI 執行失敗。
4. 主產物與已知附屬檔案的位置及狀態，區分新增、修改、既有與未產生；失敗時不能把舊檔案說成本次產出。
5. 經清理的問題分類與處理方向。錯誤時不保存任意例外文字或遠端 traceback。
6. 本次例外提供的續跑工作目錄與持久化狀態；僅在有證據時提供續跑指引。
7. 下一階段或修正設定後重新執行的指引。

不記錄原始命令列、密鑰、環境檔內容、URL、Cookie、提示詞、Agent 回答、來源原文或任意供應商錯誤訊息。報告不是完整日誌，也不是題目生成依據報告或評估分析報告的替代品。檔案路徑本身可能包含本機名稱，分享前仍需檢查。

## 相容與驗收

- 報告與主要產物的原子發布、checkpoint、完成標記分開；報告失敗不回滾主產物。
- 不修改資料集、回答、評估的資料 schema；不加入 Skill 指紋或管理檔案。
- 測試所有主流程、Skill 範本、失敗／取消／確認路徑、解析錯誤、碰撞與寫入退回。
- 測試五種介面語言、英文退回、日誌同步、隱私及既有檔案辨識。
- 執行相關回歸測試與文件檢查。離線測試不能宣稱已驗證真實模型品質。
